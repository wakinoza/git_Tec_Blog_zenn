## 1\. なぜLinuxのアクセス管理が厳格なのか？

Linux初心者が驚くことの一つが、「許可がありません（permission denied）」というエラーでしょう。

WindowsやmacOSと比べて、Linuxはアクセス権限が厳格です。
そのため、知らずにアクセス権限外のコマンドを実行してしまい、「許可がありません（permission denied）」 エラーを出してしまうケースがよく見られます。

しかし、普段使うWindowsやmacOSでこのようなエラーを見ることは稀です。
なぜ、Linuxはアクセス権限がこれほど厳格なのでしょうか？
その理由は、Linuxがもともと「マルチユーザー」を想定して作られたOSだったことにあります。

Linuxのベースとなったのは、1960～70年代に開発された「UNIX」というOSです。
当時のコンピュータ（メインフレーム）は、部屋ほどの大きさがあり、かつ高価であったため、個人や研究室単位で独占できるものではありませんでした。
そのため、1つのメインフレームを何百人もの研究者が共同して利用することが一般的でした。

1つのリソースを複数名が利用するとなると、「ルール」が必要になります。
各利用者のテリトリーを分けないと、他の利用者のプログラムのせいで自分の計算が失敗するなんて事態が発生します。
また、データの管理権限を明確にしないと、自分のデータを他の人が誤って削除してしまうという事態も起こりえます。
そのため、「どこまでが自分が好きにしてよいテリトリーか」「誰がどのファイルに対して何をしていいか」という境界線を明確にする必要があったのです。

単一のシステムリソース（CPU時間、メモリ、ストレージI/O）を複数のプロセスやユーザーが競合なく、かつ安全に共有するためには、カーネルレベルでの厳格なリソース隔離とアクセス制御が不可欠でした。
これが、現代のLinuxにも引き継がれているマルチユーザー前提の堅牢なセキュリティモデルの基礎となっています。

## 2\. パーミッション

Linuxのアクセス権限（パーミッション）の基本は、「所有ユーザーがファイル・ディレクトリのアクセス権限を自由に定める」です。

各ファイルやディレクトリには、パーミッションが付与されており、所有ユーザーが自由にパーミッションを変更できます。
逆に、他のユーザーが作成したファイルやディレクトリのパーミッションは、基本的に操作できません。

:::message
パーミッションにおいて、例外となるのが特権ユーザー（rootユーザー）です。
rootユーザーは、設定されているパーミッションを無視して、すべてのファイル・ディレクトリに対して閲覧・削除・実行ができ、パーミッションの変更も可能です。（※ファイルの実行については、いずれかのユーザーカテゴリに実行権限が付与されている必要があります）
rootユーザーの権限は非常に強いため、通常業務には用いず、rootユーザーでなければ対応できない案件でのみ利用することが推奨されます。
:::

## 3\. パーミッションの3つの範囲

では、Linuxのパーミッションの仕組みを見ていきましょう。

パーミッションは、「所有ユーザー (User)」「所有グループ (Group)に属するユーザー」「その他 (Others)のユーザー」の3種類のカテゴリで設定可能です。

| 設定範囲         | 説明                                                       |
| ---------------- | ---------------------------------------------------------- |
| 所有ユーザー     | ファイルやディレクトリを作成したユーザー                   |
| 所有グループ     | 所有ユーザーが所属しているグループの1つ                    |
| その他のユーザー | 所有ユーザーでもなく、所有グループにも属していないユーザー |

所有ユーザーが複数のグループに所属している場合は、「プライマリグループ」が所有グループとなります。
プライマリグループとは、各ユーザーが「デフォルト」として設定したグループを指します。ユーザー1人につき、プライマリグループが1つだけ指定されています。

自分のプライマリグループを確認したい場合は、`id`コマンドを実行してください。

```Bash
 id
```

コマンド実行後は、以下の情報が表示されます。

```Bash
uid=1001(myuser)
gid=1001(myuser)
groups=1001(myuser),4(admin),1002(develop),1003(vps-users)
```

| 項目   | 結果                                               |
| ------ | -------------------------------------------------- |
| uid    | ユーザーの識別番号とユーザー名                     |
| gid    | プライマリグループの識別番号とユーザー名           |
| groups | 所属しているすべてのグループの識別番号とユーザー名 |

gid項目のグループが、あなたのプライマリグループです。
ファイルやディレクトリを作成した際には、このプライマリグループが、自動的にパーミッションの所有グループとなります。

所有グループは、ファイルやディレクトリ作成後でも変更できます。
変更方法は、後述します。

## 4\. ファイルとディレクトリのパーミッション

では、コマンドでファイルのパーミッションを確認してみましょう。
パーミッションを確認したいファイルがあるディレクトリに移動し、`ls -l`コマンドを実行してください。

```Bash
ls -l
```

各ファイルやディレクトリの詳細情報が、以下のように表示されます。

```Bash
-rwxr--r-- 1 root root 100 Mar 1  2026 file1
```

| 1列目                          | 2列目          | 3列目        | 4列目        | 5列目          | 6列目        | 7列目      |
| ------------------------------ | -------------- | ------------ | ------------ | -------------- | ------------ | ---------- |
| -rwxr--r--                     | 1              | root         | root         | 100            | Mar 1  2026  | file1      |
| ファイルの種類とパーミッション | ハードリンク数 | 所有ユーザー | 所有グループ | ファイルサイズ | 最終更新日時 | ファイル名 |

パーミッションについての詳細は、1列目の「ファイルの種類とパーミッション」に記載されています。

まず、1番左の1文字が、ファイルの種類を表します。

| 表示 | 説明               |
| ---- | ------------------ |
| -    | 通常ファイル       |
| d    | ディレクトリ       |
| l    | シンボリックリンク |

シンボリックリンクについては、以下の記事をご覧ください。

https://zenn.dev/wakinoza/articles/cd6efd20fa56aa

残りの9文字がパーミッションを表します。
左側の3文字が所有ユーザー、中央の3文字が所有グループ、右側の3文字がその他のユーザーのパーミッションを示します。

| 1文字目        | 2~4文字目                    | 5~7文字目                    | 8~10文字目                       |
| -------------- | ---------------------------- | ---------------------------- | -------------------------------- |
| -              | rwx                          | r--                          | r--                              |
| ファイルの種類 | 所有ユーザーのパーミッション | 所有グループのパーミッション | その他のユーザーのパーミッション |

各カテゴリのパーミッションは、3つの権限の組み合わせで決められています。

| 記号 | 説明                  | ファイルへの権限                   | ディレクトリへの権限                                                                                                 |
| ---- | --------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| r    | 読み取り権限（read）  | ファイル内容の参照（cat,lessなど） | ディレクトリ内の内容を参照（ls,findなど）                                                                            |
| w    | 書き込み権限（write） | ファイルに書き込み（vimなど）      | ディレクトリ内での新規ファイルの作成・削除、ファイルの名前変更（touch,mv,rmなど）（通常は実行権限 x と組み合わせる） |
| x    | 実行権限（execute）   | ファイルを実行                     | ディレクトリへの移動、ディレクトリ内へのアクセス（cd）                                                               |
| -    | 権限なし              |                                    |                                                                                                                      |

「---」は権限なしを表し、「rwx」は全権限が与えられていることを表します。
「r--」のように1つの権限だけ指定することも、「rw-」のように2つの権限を組み合わせることも可能です。

ディレクトリへの権限は、各権限と許可される行為が直感的に理解しにくい面もあります。
その場合は、ディレクトリをファイル名の一覧表だと考えるとわかりやすいかもしれません。

概念的には、ディレクトリは「ファイル名とinode番号」の対応表とも言えます。
そのため、ディレクトリへの読み取り権限とは、ディレクトリの中身である「一覧表」を読み取る作業とも言えます。
また、書き込み権限は、一覧表への追加書き込み（ファイルの新規作成）・変更（ファイル名変更）・削除（ファイル削除）とも言えます。
実行権限は、ディレクトリの内部を検索したり、移動したりするための権限です。Linuxでは、特定のディレクトリに実行権限がないと、その配下のディレクトリやファイルへアクセスできません。つまり、ディレクトリの実行権限は「通過するための権限」とも言えます。

## 5\. パーミッションの数値表現

パーミッションの表現方法には、文字を用いた記号表現のほかに「数値表現」があります。
数値表現では、各権限に8進数の数字を割り当て、数字の合計でパーミッションを表現します。

| 権限     | 読み | 書き | 実行 |
| -------- | ---- | ---- | ---- |
| 記号表現 | r    | w    | x    |
| 数値表現 | 4    | 2    | 1    |

「rwx」は、4+2+1=7
「rw-」は、4+2=6
「r-x」は、4+1=5
「r--」は、4
「---」は、0

## 6\. ファイル・ディレクトリ作成時のパーミッションの指定

ファイルやディレクトリにはデフォルトのパーミッションが決められています。
そのため、デフォルトとは異なるパーミッションを指定したい場合は、明示的にパーミッションを指定します。
まず、ファイルやディレクトリ作成時に、パーミッションを指定する方法を紹介していきます。

### 6.1\. ディレクトリ作成時のパーミッションの指定

まずは、ディレクトリ作成時の指定方法です。
新規ディレクトリ作成には、`mkdir`コマンドを利用しますが、その際に「-m」オプションを指定することで、パーミッションを明示できます。

```Bash
# mkdir -m パーミッション表現 ディレクトリ名
mkdir -m 755 new_dir
```

`ls -l`コマンドを実行すると、以下の情報が表示されます。

```Bash
drwxr-xr-x 1 myuser myuser 4096 Mar 20 2026  new_dir
```

ちなみに、パーミッションの指定は、数値表現のほかに、記号表現でも可能です。
記号表現の場合は、「カテゴリ=権限」の形で表現します。
カテゴリは、以下の通りです。

| カテゴリ                | 記号 |
| ----------------------- | ---- |
| 所有ユーザー(user)      | u    |
| 所有グループ(group)     | g    |
| その他のユーザー(other) | o    |
| 全てのカテゴリ          | a    |

「,」（カンマ）区切りで1列に表記し、複数のカテゴリで同一のパーミッションを指定する場合は、カテゴリを結合して表記できます。（「g=r,o=r」を「go=r」と表記可能）
3つのカテゴリのパーミッションが同一の場合は、カテゴリをまとめて「a」と表記できます。（「u=r,g=r,o=r」は「a=r」と表記できる。）

「rwxr-xr--」は、「u=rwx,g=rx,o=r」
「rwxr-----」は、「u=rwx,g=r,o=」
「rwxr--r--」は、「u=rwx,go=r」
「rw-rw-rw-」は、「a=rw」と表現します。

先ほどのディレクトリ作成コマンド(755)は、記号表現の場合は以下の通りになります。
```Bash
mkdir -m u=rwx,go=rx new_dir
```
### 6.2\. ファイル作成時のパーミッションの指定

ファイル作成には、`touch`コマンドを実行するのが一般的です。
しかし、`touch`コマンドにはパーミッションを指定するオプションがありません。
そのため、一般的には、touch でファイルを作成したあとに、chmod でパーミッションを変更します。

```Bash
touch new_file
chmod 644 new_file
```

ここでは、ややトリッキーですが、パーミッションを指定しながらファイルを新規作成する方法を紹介していきます。
`install`コマンドを利用することで、1コマンドで、パーミッションを指定してファイルを新規作成していきます。

`install`コマンドは、「ファイルをコピーしつつ、所有者・パーミッションを設定して配置する」ためのコマンドです。

`install`コマンドで、コピー元に常に空データを返す特殊ファイル（/dev/null）を指定することで、パーミッションを指定した状態で、空ファイルを新規作成できます。

```Bash
# install -m  パーミッション情報 コピー元（常に空データを返す特殊ファイル）ファイル名
install -m 644 /dev/null new_file
```
`ls -l`コマンドを実行すると、以下の情報が表示されます。

```Bash
-rw-r--r-- 1 myuser myuser 0 Mar 20 2026  new_file
```

## 7\. 所有ユーザー、所有グループの変更

ここからは、ファイルやディレクトリを作成した後に、パーミッションを変更する方法を説明していきます。

まずは、所有ユーザーと所有グループの変更です。
ファイルやディレクトリ作成後に、所有ユーザーや所有グループを変更することは可能ですが、変更には制限があります。

所有ユーザーを変更できるのは、特権ユーザーである「rootユーザー」だけで、一般ユーザーは変更できません。rootユーザーは、所有ユーザーをどのユーザーにも自由に変更することができます。

次に所有グループの変更ですが、変更が可能なのはrootユーザーと所有ユーザーだけです。rootユーザーはどのグループにも自由に変更できますが、所有ユーザーは、自身が所属するグループにしか変更することができません。

一般ユーザーの、所有ユーザー・グループの変更に制限がある理由は、個々のユーザーが操作できる範囲を明確にするためです。
もし、一般ユーザーが、所有ユーザー・グループを自由に変更できてしまうと、ユーザーのテリトリーを侵害することが可能になるのです。
例えば、悪意のある一般ユーザーが、自分の管轄外である「admin」グループの情報を得たいと考えたとします。悪意のあるユーザーは、自分が作成したディレクトリにそれらしい名前を付けて、所有グループを「admin」に変更します。すると、「admin」グループのユーザーからすれば、知らないうちに自分たちが所属するグループの所有するディレクトリが増えていることになります。そのまま、気づかずに、ディレクトリにグループ内しか公開してはならないファイルを格納してしまうと、所有ユーザーである悪意のあるユーザーからファイルが閲覧できてしまいます。

このような領域侵犯が起きないようにするため、一般ユーザーは所有ユーザーの変更はできず、所有グループも自分のテリトリー範囲である、自分が所属するグループ内でしか変更できない仕組みになっています。

それを踏まえたうえで、所有ユーザーと所有グループの変更コマンドを見ていきましょう。

まずは、所有ユーザーの変更です。この変更はrootユーザーにしかできません。
所有ユーザーの変更には、`chown`コマンドを利用します。
ファイルfileの所有ユーザーをnew_ownerに変更する場合は、以下のコマンドを実行してください。

```Bash
# chown 新規所有ユーザー名　変更するファイル・ディレクトリ名
chown new_owner file
```

次に、所有グループの変更です。所有ユーザーは、自身が所属するグループ内で変更できます。
所有グループの変更には、`chgrp`コマンドを利用します。
ファイルfileの所有グループをnew_groupに変更する場合は、以下のコマンドを実行してください。

```Bash
# chgrp 新規所有グループ名 変更するファイル・ディレクトリ名
chgrp new_group file
```

先ほどの`chown`コマンドを利用して、所有グループを変更することもできます。所有グループを変更する場合は、新しいグループ名の前に「:」を付け加えます。
記号は「.」も利用できましたが、ユーザー名に 「.」が含まれる場合に解釈が難しくなるため、現在は非推奨です。

```Bash
chown :new_group file
```

`chown`コマンドを利用すると、所有ユーザーと所有グループを１コマンドでまとめて変更することができます。所有ユーザーを変更する場合は、rootユーザー権限が必要です。

```Bash
chown  new_owner:new_group file
```

「-R」オプションを使用すると、指定したディレクトリ、およびその配下にあるファイルの所有ユーザー・グループを再帰的に変更できます。

```Bash
chown -R new_owner:new_group dir
```

## 8\. アクセス権限の変更

次に、アクセス権限の変更を説明します。
「所有ユーザー」「所有グループ」「その他ユーザー」に付与されるアクセス権限は、ファイル・ディレクトリ作成後に変更できます。
ただし変更できるのは、rootユーザーと所有ユーザーのみです。所有グループのメンバーもアクセス権限の変更はできません。
Linuxにおいて、ファイルやディレクトリのアクセス権限をコントロールする権限は、その所有ユーザー（およびrootユーザー）にあります。所有ユーザーは、自分のファイルやディレクトリを他者にどの程度公開するかを自由に設定できます。

アクセス権限を変更したい場合は、`chmod`コマンドを利用します。
パーミッションの指定は、数値表現と記号表現の両方が利用できます。

まず、数値表現で新しいパーミッションを指定する場合は、以下のコマンドを実行します。

```Bash
#chmod パーミッション　ファイルやディレクトリ名
chmod 711 file
```

次に、記号表現です。
記号表現でパーミッションを指定する場合は、元のパーミッションから何を加えて何を減らすかという情報を「+」「-」で表現します。

「rw-rw-rw-」を「rw--w-r--」と変更したい場合は、「g-r,o-w」
「rw-rw-rw-」を「rw-------」と変更したい場合は、「go-rw」
「rw-------」を「rwxr-----」と変更したい場合は、「u+x,g+r」と記載します。

```Bash
#「rwx------」を「rwx-r--r--」と変更したい場合
chmod go+r file
```

「-R」オプションを使用すると、指定したディレクトリ、およびその配下にあるファイルのパーミッションを再帰的に変更できます。

```Bash
chmod -R 711 dir
```

## 9\. デフォルトパーミッションの設定

これまで、ファイルやディレクトリのパーミッションを個別に設定・変更する方法を紹介してきました。
しかし、複数のファイルのパーミッションを、個別に変更するのは煩雑です。

パーミッションには、システムで定められている「初期値」（デフォルトパーミッション）は設定されています。パーミッションを指定せずに作成したファイルやディレクトリは、デフォルトパーミッションが適用されています。

この、デフォルトパーミッションを調整することで、以後に作成するファイルやディレクトリのパーミッションを設定しなくても、任意のパーミッションを付与することが可能になります。
umask コマンドによる設定変更は、一時的な変更です。変更を指示したシェル（プロセス）の中だけで有効であるため、そのシェルを閉じたり、システムをログアウトすると、デフォルトパーミッションはもともとの設定に戻ります。

デフォルトパーミッションに関連する操作は、`umask`コマンドを利用します。
`umask`コマンドを引数なしで実行すると、現在のデフォルトパーミッションが表示されます。

```Bash
umask
```

デフォルトパーミッションにおいて注意すべき点は、新規作成されるファイルに自動で実行権限を付与する設定ができない仕様になっていることです。

実行権限付きのデフォルトパーミッションを設定できない理由は、セキュリティ上のリスクのためです。
仮にデフォルトで実行権限が付与できるシステムだった場合、その後作成されるファイルには自動的に実行権限が付与されてしまいます。もしそのような状態であれば、インターネットからダウンロードしたファイルや未完成のスクリプトファイルまですべて「いつでも実行可能なプログラム」とシステムに認識されてしまい、意図しないファイルが実行されてしまうリスクが大きくなります。もし、ウイルスなどの不正プログラムが実行されてしまえば、セキュリティ上非常に危険です。
このような理由のため、ファイルを新規作成する際は、最初から実行権限を要求しない（最大でも 666 をベースにする）仕様になっています。これにより、umask でどれだけ権限を開放していても、新規作成されたファイルに自動で実行権限が付与されるのを防いでいます。

では、具体的な指定方法を説明していきます。
新しいパーミッションを設定する場合、記号表現と数値表現を両方利用できます。

記号表現で指定する場合は、ディレクトリ作成時のパーミッションの指定時と同様に「=」記号で表現します。
また、記号表現を利用する場合は、「-S」オプションを追記します。

```Bash
#「rw-rw----」を指定する
umask -S ug=rw,o=
```

数値表現でパーミッションを指定する場合は、さらに注意が必要です。
デフォルトパーミッションを数値表現で指定する場合は、「何を許可するか」ではなく「何を許可しないか」と指定します。
`umask`コマンドで、拒否したい権限を数値で指定すると、指定パーミッション値の論理反転と、ベースパーミッションの論理積によって、デフォルトパーミッションとして設定されます。
実務では「666/777 から umask を引く」と覚えられることも多いですが、内部的にはビット演算で計算されています。

数式で表現すると以下のようになります。

デフォルトパーミッション = ベースパーミッション AND (NOT umaskの指定パーミッション)

ベースパーミッションは、ファイルで「666」(実行権限が要求されないので「rw-rw-rw-」)、ディレクトリでは「777」となっています。
例を見ていきましょう。

`umask 037`コマンドを設定したとしましょう。
初期値は、ファイルは「666」、ディレクトリ「777」です。

まず、ファイルの所有ユーザーの桁から計算していきます。
1. 所有ユーザーのベースパーミッション「6」は、2進数では「110」（r=1,w=1,x=0）
2. umaskのパーミッションは「0」は、2進数で「000」（r=0,w=0,x=0）
3. 「NOT umask」でumaskのパーミッションのビットを反転、「000」→「111」
4. ベースパーミッションと反転したumaskの論理積を取ります。110 AND 111 = 110
5. 「110」は8進数で6(rw-)となります。

同様に所有グループの桁は、
1. 所有グループのベースパーミッション「6」は、2進数では「110」（r=1,w=1,x=0）
2. umaskのパーミッションは「3」は、2進数で「011」（r=0,w=1,x=1）
3. 「NOT umask」でumaskのパーミッションのビットを反転、「011」→「100」
4. ベースパーミッションと反転したumaskの論理積を取ります。110 AND 100 = 100
5. 「100」は8進数で4(r--)となります。

同様の計算で、その他ユーザーの桁は、
110 AND (NOT 111) = 000 となり8進数で0（---）となります。

3つのカテゴリを合計すると、ファイルのデフォルトパーミッションは 「640」となります。

ディレクトリのデフォルトパーミッションも同様に計算します。
  - 所有ユーザーは、111 AND (NOT 000) = 111 となり8進数で7（rwx）
  - 所有グループは、111 AND (NOT 011) = 100 となり8進数で4（r--）
  - その他ユーザーは、111 AND (NOT 111) = 000 となり8進数で0（---）

3つのカテゴリを合計すると、ディレクトリのデフォルトパーミッションは 「740」となります。

```Bash
umask 037

# ファイルのデフォルトパーミッションは「640（rw-r-----）」となります。
# ディレクトリのデフォルトパーミッションは、「740（rwxr-----）」となります。
```

umaskの設定は、一時的な変更です。
変更を永続化したい場合は、bashrc や /etc/profile に記述します。

## まとめ

- アクセス制御の背景 : Linuxの厳格な権限管理は、UNIX由来のマルチユーザー環境におけるリソース隔離と堅牢なセキュリティモデルに根差している。
- 権限の3カテゴリと3属性 : 権限は「所有ユーザー」「所有グループ」「その他」の3範囲に対し、読み取り(r=4)・書き込み(w=2)・実行(x=1)の組み合わせで定義される。
- 所有権変更の厳格な制約 : セキュリティの観点から、所有ユーザーの変更（`chown`）はroot権限に限定され、グループ変更（`chgrp`）も厳密に制限されている。
- パーミッションの指定 : 権限の変更（`chmod`）や作成時の明示（`mkdir -m`、`install -m`）は、8進数の数値表現および記号表現で柔軟に制御可能である。
- デフォルト権限の算出 : 新規作成時の権限は、ベースパーミッション（ファイル666/ディレクトリ777）と`umask`値のビット演算（論理反転と論理積）によって決定される。
- 安全性を担保する基本設計 : 不正なプログラムの自動実行を防ぐため、どれほど`umask`を開放しても新規ファイルにはデフォルトで実行権限が付与されない仕様となっている。
