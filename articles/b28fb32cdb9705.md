## 1\. AssertJとは

ユニットテストにおいて、期待値と実測値を検証するのにアサーションという検証用メソッドを利用します。

アサーションは、JavaのテストフレームワークであるJUnit5でも提供されていますが、オープンソースのアサーションライブラリを使うとより効率的に記載することができます。
現在多く使われているアサーションライブラリの一つが、「AssertJ」です。

JUnit公式のアサーションメソッドを使ったコードと、AssertJを利用したコードを見比べてみましょう。

以下がJUnit5公式アサーションを使用したコード例です。

```Java
int age = 30;
String name = "Alice";

// 年齢の検証（18歳以上、かつ65歳未満）
assertTrue(age >= 18, "18歳以上であること");
assertTrue(age < 65, "65歳未満であること");

// 名前の検証（nullでなく、20文字以内）
assertNotNull(name, "名前はnullでないこと");
assertTrue(name.length() <= 20, "名前は20文字以内であること");

```

検証方法によって、assertTrueメソッドとassertNotNullメソッドを使い分けています。
また、検証ごとにメソッドを書く必要があります。

以下が、AssertJのアサーションメソッドを使用したコード例です。

```Java
int age = 30;
String name = "Alice";

// 年齢の検証
assertThat(age)
    .isGreaterThanOrEqualTo(18)
    .isLessThan(65);

// 名前の検証
assertThat(name)
    .isNotNull()
    .hasSizeLessThanOrEqualTo(20);
```

AssertJでは、検証のほとんどはassertThat()を起点に記述します。assertThatの引数に実測値を渡し、「.」(ドット)の後に検証用のメソッドを複数繋げることができます（メソッドチェーン） このように一時変数を作らずに「流れるような」テストコードを書ける点が、AssertJの特徴です。

また、assertThat()引数の型に応じて、IDEの補完機能が後に続く検証メソッド（Stringなら startsWith、Listなら contains など）を提示するため、APIを記憶していなくても迷わず記述できるのが大きな利点です。

さらに、assertThat以後のメソッドは、英語の語順に似ています。

age is Greater Than Or Equal To 18
age is Less Than 65
name is Not Null
name has Size Less Than Or Equal To 20

このため、APIの役割を記憶していなくても、何を検証しているのかをコードから容易に理解できます。

他にも、AssertJでは、エラーメッセージの情報量が多いため原因の特定が容易であるという利点もあります。


また、AssertJと並んでよく使われるオープンソースのアサーションライブラリに「Hamcrest」があります。

Hamcrestも非常に有用なライブラリではありますが、メソッドを追加するごとにstaticインポートが必要であったり、後に説明する再帰比較が標準機能として提供されていない、などの違いがあります。

この記事では、AssertJの記述方法について、代表的なものをまとめていきます。

## 2\. 導入準備

AssertJはJUnit5の公式機能ではないため、利用するには導入準備が必要です。

Mavenなどのビルドツールに依存関係を追加するのが、簡単な方法です。

Mavenの場合は、pom.xmlファイルの`<dependencies>`セクションに以下を追加します。
2026年2月時点の最新版は、以下の通りです。（最新版の依存関係は、随時AssertJ公式GitHubを参照してください）

```XML:pom.xml
<dependency>
  <groupId>org.assertj</groupId>
  <artifactId>assertj-core</artifactId>
  <version>3.27.6</version>
  <scope>test</scope>
</dependency>
```

依存関係を記載した後、テストクラスにstaticインポートします。

```Java
import static org.assertj.core.api.Assertions.*;
```

これで、AssertJの準備は完了です。

## 3\. 基本のアサーション

AssertJは、assertThat(実測値)の後に、検証用メソッドをつなげて記載します。
この章では、基本的な検証用メソッドをまとめていきます。
なお、引数の「expected」は期待値を指します。

| メソッド            | 説明                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| isEqualTo(expected) | equals()メソッドで等価であるかを検証します                           |
| isNull()            | nullであるかを検証します                                             |
| isNotNull()         | nullでないことを検証します                                           |
| isTrue()            | trueであるかを検証します                                             |
| isFalse()           | falseであるかを検証します                                            |
| isSameAs(expected)  | 実測値のオブジェクトが期待値と同一のインスタンスであるかを検証します |
| isInstanceOf(Class) | 特定の型のインスタンスであるかを検証します                           |

```Java
import static org.assertj.core.api.Assertions.assertThat;
import org.junit.jupiter.api.Test;

class UserAssertionsTest {

    @Test
    void testUserOperations() {
        //基本的な値の検証 (isEqualTo, isTrue)
        String status = "ACTIVE";
        boolean isAdmin = true;
        int loginCount = 0;

        assertThat(status).isEqualTo("ACTIVE"); // 等価性
        assertThat(isAdmin).isTrue();           // 真理値

        // Nullチェック (isNull, isNotNull)
        String middleName = null;
        String firstName = "Taro";

        assertThat(middleName).isNull();
        assertThat(firstName).isNotNull();

        //インスタンスの検証 (isInstanceOf)
        Object obj = "Hello AssertJ";
        assertThat(obj).isInstanceOf(String.class);

        // 同一性の検証 (isSameAs)
        String str1 = new String("Java");
        String str2 = str1;
        String str3 = new String("Java");

        assertThat(str1).isSameAs(str2);
        assertThat(str1).isEqualTo(str3);
        // assertThat(str1).isSameAs(str3);  // この検証は失敗する（インスタンスの参照先が異なるため）
    }
}
```

## 4\. 数値のアサーション

| メソッド                           | 説明                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| isPositive()                       | 実測値が 0 より大きいかを検証します                                            |
| isNegative()                       | 実測値が 0 より小さいかを検証します                                            |
| isGreaterThan(value)               | 実測値が指定した値より大きいか（超過）を検証します（境界値はエラーとなります） |
| isLessThan(value)                  | 実測値が指定した値より小さいか（未満）を検証します（境界値はエラーとなります） |
| isGreaterThanOrEqualTo(value)      | 実測値が指定した値を含めて大きいか（以上）を検証します                         |
| isLessThanOrEqualTo(value)         | 実測値が指定した値を含めて小さいか（以下）を検証します                         |
| isBetween(start, end)              | 実測値が指定した範囲内（開始点と終了点を含む）にあるかを検証します。           |
| isStrictlyBetween(start, end)      | 実測値が指定した範囲内（開始点と終了点を含まない）にあるかを検証します。       |
| isCloseTo(expected, within(delta)) | 浮動小数点数（double, float）の計算で、微小な誤差を許容して検証します。        |

```Java
//基本的な価格の検証 (isEqualTo, isPositive)
int basePrice = 1000;
assertThat(basePrice)
    .isPositive()
    .isEqualTo(1000);

// 割引率の検証 (isBetween)
int discountRate = 10; // 10%
assertThat(discountRate).isBetween(0, 100);

// 年齢制限などの境界値検証 (isGreaterThanOrEqualTo)
int targetAge = 18;
assertThat(targetAge).isGreaterThanOrEqualTo(18);

// 浮動小数点数の計算検証 (isCloseTo)
double priceWithTax = 1000 * 1.1;

// 「1100.0 に対して、0.01 までの誤差なら許容する」という意味
assertThat(priceWithTax).isCloseTo(1100.0, within(0.01));

// 複数の状態をまとめて検証
int stockCount = 5;
assertThat(stockCount)
    .isNotZero()
    .isLessThan(10);
```

補足として、なぜ浮動小数点数の比較に isCloseTo が必要なのかを説明します。
コンピュータ内部では、数値は2進数で処理されます。そのため、値が無限小数となると、メモリの有限なビット数に収める際に必ず微小な丸め誤差（Rounding Error）が発生します。
厳密な一致を検証するisEqualToを使用すると、計算結果がわずかにずれただけでテストが失敗してしまいます。
このような丸め誤差が発生する可能性があるテストコードでは、within(delta) を用いて「許容可能な誤差の範囲」を明示的に指定します。これにより、丸め誤差による検証失敗が回避できます。

## 5\. 文字列のアサーション

| メソッド                        | 説明                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------ |
| isEqualToIgnoringCase(expected) | 大文字と小文字と区別せず、文字列が同じか検証する                               |
| contains(values...)             | 指定した文字列が含まれているかを検証します。引数に複数のキーワードを指定できる |
| doesNotContain(values...)       | 指定した文字列が含まれないかを検証します。引数に複数のキーワードを指定できる   |
| isBlank()                       | null、空文字または空白文字のみの状態かを検証します                             |
| isNotBlank()                    | null、空文字または空白文字のみのいずれの状態でもないかを検証します             |
| startsWith(prefix)              | 特定の文字で始まっているかを検証します                                         |
| endsWith(suffix)                | 特定の文字で終わっているかを検証します。                                       |
| hasSize(expectedSize)           | 文字列が指定した長さかを検証します。                                           |
| matches(regex)                  | 形式が正しいかを正規表現で検証します。                                         |
| containsOnlyDigits()            | 文字列が数字（0-9）だけで構成されているかを検証します。                        |
| containsWhitespaces()           | 文字列内にスペースが含まれているかを検証します                                 |
| doesNotContainAnyWhitespaces()  | 文字列内にスペースが含まれていないことを検証します                             |

```Java
//  完全一致と大文字小文字の無視 (isEqualTo, isEqualToIgnoringCase)
String role = "ADMIN";
assertThat(role).isEqualTo("ADMIN");
assertThat(role).isEqualToIgnoringCase("admin");

// 部分一致 (contains)
String errorMessage = "Error: User ID [123] not found";
assertThat(errorMessage).contains("User ID", "not found");

// 空白・空文字の検証 (isNotBlank)
String inputName = "Taro Yamada";
assertThat(inputName).isNotBlank(); // null, "", " " ではないこと

// 前方・後方一致 (startsWith, endsWith)
String fileName = "report_2026.pdf";
assertThat(fileName).startsWith("report_").endsWith(".pdf");

// 文字数と数字のみの検証 (hasSize, containsOnlyDigits)
String zipCode = "1234567";
assertThat(zipCode).hasSize(7).containsOnlyDigits();

// 正規表現による形式チェック (matches)
String empId = "STF-9876";
assertThat(empId).matches("^[A-Z]{3}-\\d{4}$");
```

## 6\. 配列・コレクションのアサーション

まずは、配列やListで使われるアサーションです。

| メソッド                             | 説明                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------ |
| hasSize(expected)                    | 配列やコレクションの件数が指定された値と一致するかを検証します。         |
| isEmpty()                            | 空かを検証します。                                                       |
| isNotEmpty()                         | 要素が入っているかを検証します                                           |
| containsExactly(values...)           | 複数の要素が「順番通り」かつ「過不足なく」一致しているかを検証します。   |
| containsExactlyInAnyOrder(values...) | 順番はバラバラでもいいが、「過不足なく」一致しているかを検証します。     |
| containsOnlyOnce(values...)          | 指定した要素が「ちょうど1回だけ」含まれているかを検証します              |
| hasSameElementsAs(Iterable)          | 別のコレクションと中身が（順不同で）完全に一致するか検証します           |
| startsWith(values...)                | 最初が指定した要素であるかを検証します。                                 |
| endsWith(values...)                  | 最後が指定した要素であるかを検証します。                                 |
| allSatisfy(condition)                | 全要素が、指定した条件を満たしているかを検証します（ラムダ式を使います） |

上のアサーションのうち、順番を問わないcontainsExactlyInAnyOrder()、hasSameElementsAs()、allSatisfy()などは、Setにも利用できます。

Key-Value形式の検証が必要なMap特有のアサーションは、以下の通りです。

| メソッド                        | 説明                                          |
| ------------------------------- | --------------------------------------------- |
| containsKey(key)                | 特定のキーが存在するかを検証します            |
| containsKeys(keys...)           | 特定の複数のキーが存在するかを検証します      |
| containsValue(value)            | 特定の値が存在するかを検証します              |
| containsEntry(key, value)       | キーと値のペアが正しく存在するかを検証します  |
| extractingFromEntries(Function) | Mapのエントリから特定の値を抽出して検証します |

```Java
// Listの検証
List<String> colors = List.of("Red", "Green", "Blue");
assertThat(colors).hasSize(3).containsExactly("Red", "Green", "Blue");

// Setの検証 （allSatisfy）
Set<Integer> scores = Set.of(85, 92, 78);
assertThat(scores).allSatisfy(score -> {
    assertThat(score).isGreaterThan(70); // 全員70点より高いこと
    assertThat(score).isLessThan(100); // 全員100点未満であること
});

// Mapの検証
Map<Integer, String> userMap = Map.of(1, "Taro", 2, "Hanako", 3, "John");

assertThat(userMap).hasSize(3).containsEntry(1, "Taro").containsKey(2);

// extractingFromEntries
// Mapのエントリ（Key-Valueのペア）から値(Value)だけを抽出してリストとして検証
assertThat(userMap)
    .extractingFromEntries(Map.Entry::getValue)
    .containsExactlyInAnyOrder("Taro", "Hanako", "John");
```

## 7\. オブジェクトのアサーション

自作クラスは、検証項目も多く、オブジェクトのフィールドに子オブジェクトがあれば子オブジェクトまで検証しなければなりません。

また、isEqualTo()はequalsメソッドを基に検証を行っています。そのため、自作クラスにequalsメソッドをオーバーライドしていないと、isEqualTo()が失敗してしまいます。

このように何かとテストコードが煩雑になりがちなオブジェクト検証ですが、AssertJでは簡潔にテストコードを記述できるアサーションが多く提供されています。

| メソッド                                 | 説明                                                                                                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| extracting(Function... / String...)      | オブジェクトから値を取り出し、そのまま次の検証へ繋げます。                                                                                  |
| usingRecursiveComparison()               | オブジェクトの中にある「子オブジェクト」まで含めて、全階層を深く検証します。equalsメソッドが未実装でも、全フィールドの値を1つずつ比較します |
| hasFieldOrPropertyWithValue(name, value) | 特定の1項目だけを検証します                                                                                                                 |
| hasAllNullFieldsOrProperties()           | 全てのフィールドが null であることを検証します（初期化直後の確認など）                                                                      |
| ignoringFields(String...)                | 検証対象から外したいフィールド（自動インクリメントのIDや日時オブジェクトなど、一致しないことが自明なもの）を指定します                      |

子オブジェクトをもつオブジェクトのテストコード例は、以下の通りです。

```Java
import java.time.LocalDateTime;

//親オブジェクト
public class User {
  // hasAllNullFieldsOrProperties()の検証のため、Integer型を指定
  private Integer id;
  private String name;
  private String plan;
  private LocalDateTime createdAt;
  private Address address;

  public User() {}

  public User(Integer id, String name, String plan, LocalDateTime createdAt) {
    this.id = id;
    this.name = name;
    this.plan = plan;
    this.createdAt = createdAt;
  }

  // Getter / Setter
}
```

```Java
//子オブジェクト
public class Address {
  private String city;
  private String prefecture;

  public Address(String city, String prefecture) {
    this.city = city;
    this.prefecture = prefecture;
  }
  // Getter / Setter
}
```

```Java
// テスト対象のデータ
User actualUser = new User(101, "Alice", "Free", LocalDateTime.now());
actualUser.setAddress(new Address("Nagoya", "Aichi"));

// 期待値データ
User expectedUser = new User(10, "Alice", "Free", null);
expectedUser.setAddress(new Address("Nagoya", "Aichi"));

// ピンポイント検証 (hasFieldOrPropertyWithValue)
assertThat(actualUser).hasFieldOrPropertyWithValue("name", "Alice");

// 特定フィールドの抽出 (extracting)
assertThat(actualUser).extracting(User::getName, User::getPlan).containsExactly("Alice",
    "Free");

// 再帰比較とフィールド除外 (usingRecursiveComparison,ignoringFields)
assertThat(actualUser)
    .usingRecursiveComparison()
    .ignoringFields("id", "createdAt")
    .isEqualTo(expectedUser);

// 全フィールドがNULLか確認 (hasAllNullFieldsOrProperties)
User newUser = new User();
assertThat(newUser).hasAllNullFieldsOrProperties();
```

## 8\. 日付のアサーション

| メソッド                           | 説明                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| isBefore(date)                     | 指定した日時より「前」かを検証します                         |
| isAfter(date)                      | 指定した日時より「後」かを検証します                         |
| isBeforeOrEqualTo(date)            | 指定した日時以前であるかを検証します                         |
| isAfterOrEqualTo(date)             | 指定した日時以後であるかを検証します                         |
| isBetween(start, end)              | 日時がある範囲に収まっているかを検証します。（境界値を含む） |
| isEqualToIgnoringNanoseconds(date) | ナノ秒単位を無視して検証します                               |
| isCloseTo(date, within(delta))     | 指定したズレを許容して、検証します                           |
| isToday()                          | 今日であることを検証します                                   |

```Java
assertThat(yesterday).isBefore(now);

//  範囲指定
assertThat(now).isBetween(yesterday, now.plusDays(1));

// 実行時のズレを許容する
// テスト実行中に1秒くらい過ぎても大丈夫なようにする
assertThat(now).isCloseTo(LocalDateTime.now(), within(1, ChronoUnit.SECONDS));

// 今日かどうかを検証
assertThat(LocalDate.now()).isToday();
```

## 9\. Optionalのアサーション

戻り値が「空」かもしれないことを表すOptionalの検証は、重要です。
AssertJでは、Optionalのget() を直接呼び出さずに検証できるアサーションが提供されています。

| メソッド                     | 説明                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| isPresent()                  | Optional の中に値が入っていることを検証します                         |
| isEmpty()                    | Optional が空（Optional.empty()）であることを検証します               |
| hasValue(expected)           | Optional の中身が指定した値と一致するかを検証します                   |
| hasValueSatisfying(Consumer) | Optionalの中身を取り出し、詳細な検証をラムダ式で指定します            |
| get()                        | Optional の中身を「取り出し」て、その型の通常のアサーションへ繋げます |

```Java
// 値が存在する場合
Optional<String> found = Optional.of("Success");

assertThat(found)
    .isPresent()
    .get()
    .contains("Success");

// 値が空の場合
Optional<String> notFound = Optional.empty();

assertThat(notFound).isEmpty();

// オブジェクトが入っている場合（hasValueSatisfying）
Optional<User> userOpt = Optional.of(new User(1, "Taro", "Free", null));

assertThat(userOpt).hasValueSatisfying(user -> {
    assertThat(user.getName()).isEqualTo("Taro");
    assertThat(user.getId()).isPositive();
});
```

## 10\. 例外のアサーション

これまで、最初のアサーションメソッドはすべてassertThat(actual)でしたが、例外検証の場合は、assertThatThrownBy(Callable)を利用し、引数内でラムダ式を使って、例外が発生するコードを記載します。

| メソッド                                            | 説明                                                                         |
| --------------------------------------------------- | ---------------------------------------------------------------------------- |
| hasMessage(message)                                 | エラーメッセージが一致するかを検証します                                     |
| hasMessageContaining(part)                          | エラーメッセージが指定された文字列を含むかを検証します                       |
| isInstanceOf(Class)                                 | 発生した例外が期待通りのクラス（またはそのサブクラス）であるかを確認します。 |
| hasNoCause()                                        | 例外が cause を持っていないことを検証します                                  |
| hasCauseInstanceOf(Class)                           | 別の例外が期待通りのクラスであるかを検証します                               |
| assertThatCode(Callable).doesNotThrowAnyException() | 例外が発生しないことを明示します                                             |


```Java
//  基本的な例外検証
assertThatThrownBy(() -> {
    throw new IllegalArgumentException("不正な値です: -1");
})
.isInstanceOf(IllegalArgumentException.class)
.hasMessageContaining("不正な値")
.hasMessage("不正な値です: -1")
.hasNoCause();

//  境界値などで例外が「出ない」ことの確認
assertThatCode(() -> {
    int result = 10 / 2;
}).doesNotThrowAnyException();
```

補足すると、hasNoCause() は、発生した例外が「他の例外を原因（Cause）として持っていないこと」を検証します。Javaの例外には、ある例外を別の例外で包む（ラップする）「例外チェーン」という仕組みがあります。hasNoCause() は、スローされた例外が「例外の起点そのもの」であり、他に別のエラーをラップしていないことを確認するために使います。
hasCauseInstanceOf()は、スローされた例外が別の例外をラップしていた場合に、ラップされた例外を検証します。

## 11\. その他のアサーション

最後に、検証失敗時の原因究明を容易にする機能を2つ紹介します。

- as(description, args...)

テストが失敗したときに表示されるメッセージに、「何を検証していたのか」という説明を追加します

- SoftAssertions (SoftAssertions)

通常のアサーションは、1つでも失敗すると以後の検証が止まってしまいます。
SoftAssertions を使うと、1つ失敗しても、残りのアサーションをすべて実行します。
また、検証画面では、検証失敗した箇所をまとめて報告してくれます。


```Java
@Test
// 比較用：SoftAssertionがない通常のアサーションの場合
void testNormalAssertion() {
    User user = new User(101, "Alice", "Free", LocalDateTime.now());

    // 失敗する検証
    assertThat(user.getId()).as("【通常】ユーザーID").isEqualTo(200);

    // 失敗する検証
    assertThat(user.getPlan()).as("【通常】契約プラン").isEqualTo("Premium");

}

@Test
void testUserWithSoftAssertions() {
    User user = new User(101, "Alice", "Free", LocalDateTime.now());

    SoftAssertions.assertSoftly(softly -> {

        // 成功する検証
        softly.assertThat(user.getName()).as("ユーザー名").isEqualTo("Alice");

        // 失敗する検証
        softly.assertThat(user.getId()).as("ユーザーID").isEqualTo(200);

        // 失敗する検証
        softly.assertThat(user.getPlan()).as("契約プラン").isEqualTo("Premium");
    });
}
```

まずは、Soft Assertionsを利用していないtestNormalAssertion()の結果です。

testNormalAssertion()
org.opentest4j.AssertionFailedError: [【通常】ユーザーID]
expected: 200
 but was: 101

検証結果を見ると、１つの失敗結果しか表示されていません。
１つ目の検証で失敗し、以後の検証が行われていないことがわかります。
また、asの表記により、どの項目を検証していたのかが分かりやすくなっています。

次に、SoftAssertionsを利用した検証の結果を見てみましょう。

testUserWithSoftAssertions()
org.assertj.core.error.AssertJMultipleFailuresError:
Multiple Failures (2 failures)
-- failure 1 --
[ユーザーID]
expected: 200
 but was: 101
at SoftAssertionExperimentTest.lambda$0(SoftAssertionExperimentTest.java:32)
-- failure 2 --
[契約プラン]
expected: "Premium"
 but was: "Free"
at SoftAssertionExperimentTest.lambda$0(SoftAssertionExperimentTest.java:35)

2つ目の検証が失敗していますが、最後まで検証が行われ、失敗結果がまとめて表示されています。
複数の失敗結果がありますが、asで指定したメッセージが表示されているため、どの検証に失敗したのかが一目で分かります。
