## はじめに

- Linuxの勉強をしています。
- ファイル操作中に権限エラーに遭遇したケースについて、原因と対処方法をまとめました。
- 間違い等あれば、指摘いただけると助かります。

## 結論
- Linuxであるファイルにアクセスしようとした際、ファイル自体に読み取り権限が設定されているにもかかわらず、`Permission denied` が発生するエラーに遭遇しました。

- 今回の原因は、ファイルを格納している親ディレクトリに、アクセスするユーザーの実行権限（`x`）が設定されていなかったことです。

- Linuxでは、ファイル自体に読み取り権限があっても、そこに至るまでのディレクトリを通過できなければファイルにアクセスできません。

- ファイルのアクセス権限を調べる際は、ファイル自身だけでなく、親ディレクトリの権限も確認する必要があります。今回の調査では、`namei -l` コマンドが役立ちました。


## 動作環境

- Windows11
- Oracle VirtualBox
- Ubuntu server 24.04


## 1.  発生したトラブル

発生したトラブルの状況について、状況を再現して説明します。

今回、ユーザー`testuser` が所有するファイルを読み込もうとしたところ、`Permission denied` が発生するトラブルに遭遇しました。

読み取ろうとしたファイルは次のとおりです。

```text
/tmp/permission-test/sample.txt
```

まず、現在ログインしているユーザーがだれなのかを`whoami`コマンドで確認します。

[whoamiコマンドの結果](/images/whoami.png)

`whoami`コマンドの結果、現在のユーザーは「testuser」であることがわかります。

testuserでログインした状態で、対象ファイルの情報を取得しようとすると、「Permission denied」エラーになります。
「Permission denied」エラーは、何らかの操作をしたユーザーにその操作を実行する権限がないことを示すエラーです。

続いて、別アカウントから、対象ファイルの所有者とパーミッションを`ls -l`コマンドで確認します。

[lsコマンドの結果](/images/before_ls.png)

対象ファイルの所有ユーザーが「testuser」であり、所有ユーザーに読み取り権限（`r`）が設定されていることが分かります。

つまり、現在のユーザーとファイルの所有ユーザーは一致しており、ファイル自体の読み取り権限にも問題はないように見えます。

にもかかわらず、ファイル情報を取得できませんでした。

そこで、調査対象をファイル自身から、そのファイルを格納しているディレクトリへ広げることにしました。

## 2. 原因の調査

### 2.1. nameiコマンドでパス全体を確認する

Linuxでは、ファイルにアクセスする際、対象ファイルまでのディレクトリを順番に通過する必要があります。

そのため、ファイル自身のパーミッションだけでなく、ファイルを格納するディレクトリのパーミッションも確認する必要があります。

親ディレクトリのパーミッションを一覧表示するために、`namei -l` コマンドを使用しました。

```bash
namei -l /tmp/permission-test/sample.txt
```

`namei` は、指定したパスを構成する各階層の情報を表示するコマンドです。

`-l` オプションを付けると、各階層の所有ユーザー・グループ・パーミッションを確認できます。

[nameiコマンドの結果](/images/namei.png)

この結果から、各階層のパーミッションは次のようになっていることが分かりました。

| 対象              | 所有ユーザー | 所有グループ | パーミッション |
| ----------------- | ------------ | ------------ | -------------- |
| `/`               | root         | root         | `rwxr-xr-x`    |
| `/tmp`            | root         | root         | `rwxrwxrwt`    |
| `permission-test` | linuxadmin   | linuxadmin   | `rwx------`    |
| `sample.txt`      | testuser     | testteam     | `rw-r-----`    |

### 2.2. 親ディレクトリのパーミッションに問題があった

調査結果から、エラーの原因は `permission-test` ディレクトリにあることが分かりました。

```text
drwx------ linuxadmin linuxadmin permission-test
```

このディレクトリは `linuxadmin` が所有しています。

パーミッションの `rwx------` は、所有ユーザーにのみ読み取り・書き込み・実行権限が設定されており、グループとその他のユーザーには権限がありません。

つまり、‘testuser'にはディレクトリへの読み取り・書き込み・実行権限がないということです。

この場合、ファイルの所有ユーザーと親ディレクトリの所有ユーザーが異なること自体は、問題ではありません。

今回の問題は、親ディレクトリのパーミッションが `rwx------`となっており、所有ユーザーである`linuxadmin`以外には権限が与えられていなかったことです。

`testuser` はファイル自体には読み取り権限を持っていますが、親ディレクトリである `permission-test` を通過するための実行権限（`x`）を持っていません。

そのため、ファイルに読み取り権限が設定されていても、ファイルまで到達できず `Permission denied` が発生したと考えられます。

## 3. 対策と動作確認

### 3.1. ディレクトリのパーミッションを変更する

原因は親ディレクトリの実行権限不足だした。
今回のケースでは、親ディレクトリのその他のユーザーに権限を付与しても問題ないケースであったため、ディレクトリの権限を変更する方法で対応しました。

ディレクトリの通過に必要なのは `x` 権限です。

例えば、ディレクトリのその他のユーザーに実行権限を追加する場合は、ディレクトリの所有者である `linuxadmin` でログインした状態で、`chmod`コマンドで次のように設定します。

```bash
sudo chmod o+x /tmp/permission-test
```

[chmodコマンドの結果](/images/chmod.png)

`o+x` は、その他のユーザー（other）に実行権限（execute）を追加する指定です。

:::message
実環境で、ディレクトリのその他のユーザー全員に権限を付与する方法が適切かどうかは、ディレクトリの用途やセキュリティ要件に応じて判断する必要があります。
:::

### 3.2. ファイルを再度読み込む

権限変更後、`testuser` ユーザーに切り替えて、対象ファイルを再度読み込みます。

[catコマンドの結果](/images/fileOpen.png)

変更後は、ファイルの内容を正常に読み込めることを確認できました。

これにより、親ディレクトリの権限不足が原因だったという仮説を、実際の操作で検証できました。

## 4. ファイルとディレクトリのパーミッションの違い

今回のトラブルから、ファイルとディレクトリでは同じ `rwx` でも意味が異なることを改めて確認できました。

| 権限 | ファイルの場合         | ディレクトリの場合                           |
| ---- | ---------------------- | -------------------------------------------- |
| `r`  | ファイル内容の読み取り | ディレクトリ内のファイル名一覧の取得         |
| `w`  | ファイル内容の変更     | ディレクトリ内のファイルやディレクトリの作成・削除・名前変更（通常は x も必要） |
| `x`  | ファイルの実行         | ディレクトリ内の検索・通過      |

ここで重要なのが、ディレクトリの `x` 権限です。

ディレクトリの `x` は、単なる通過だけでなく、内部のファイル名を指定してアクセスするための検索権限（search permission）という意味も持っています。

例えば、対象ファイルのパスが次のようになっているとします。

```text
/tmp/permission-test/sample.txt
```

このファイルにアクセスするには、ルートディレクトリ `/` から `/tmp`、`permission-test` まで、各ディレクトリを通過できなければなりません。

そのため、ファイル自体に読み取り権限があっても、途中のディレクトリに `x` 権限がなければアクセスできません。


##  まとめ

今回は、ファイル自体に読み取り権限が設定されているにもかかわらず、`Permission denied` が発生するトラブルを調査しました。

最初はファイルのパーミッションを確認しましたが、問題は親ディレクトリにありました。

今回のポイントは次のとおりです。

- ファイルに読み取り権限があっても、親ディレクトリを通過できなければアクセスできない
- ディレクトリの `x` 権限は、内部のファイルやディレクトリにアクセスするために必要
- ファイルとディレクトリでは、同じ `rwx` でも意味が異なる
- `namei -l` を使うと、パスを構成する各階層の所有者・グループ・パーミッションを確認できる

Linuxで `Permission denied` が発生した場合、対象ファイルのパーミッションだけで判断せず、親ディレクトリを含めて確認することが重要です。

今回のように、`ls -l` だけでは原因を特定できない場合でも、`namei -l` を使ってパス全体を調べることで、問題の箇所を絞り込めます。
