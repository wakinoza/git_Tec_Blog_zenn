## 苦戦した問題

今回挑戦した問題は以下の問題です。

[ABC400C - 2^a b^2](https://atcoder.jp/contests/abc400/tasks/abc400_c)

苦戦していた時点での私のコードは、以下の通りです。

```Java
//未完成のコードです
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        long n = scanner.nextLong();
        scanner.close();

        long goodNumberTotal = 0;
        long powerOf2 = 2;
        while (powerOf2 <= n) {
            long maxB = n / powerOf2;
            long root = (long) Math.sqrt(maxB);
            goodNumberTotal += (root + 1) / 2;
            
            if (n / 2 < powerOf2) {
              break;
            } else {
              powerOf2 *= 2;
            }
        }
        System.out.println(goodNumberTotal);
    }
}
```

ロジックも組めており、計算量も問題ないと判断して提出しても、いくつかのテストコードがWrongAnswerとなりました。

なぜ？

Geminiくんに聞いてみると、浮動小数点の丸め誤差が起きている可能性が高いと言われました。

「丸め誤差」、基本情報の勉強で名前だけ覚えたけど、理解が浅かったようです。

## 浮動小数点の丸め誤差

Java言語で小数を扱う際は、浮動小数点float型であるfloat型かdouble型を利用します。
float型とdouble型での数値の扱い方は、国際標準規格である「IEEE 754」によって定められています。
IEEE 754では、数値を 「符号 × 指数部 × 仮数部」という形式に分解し、それぞれを2進数の数値情報として保存します。

- 符号  : 正負を表します
- 指数部 : 小数点の位置を決めます
- 仮数部 : 数値の有効数字を保存します

float型とdouble型それぞれが格納できる情報量は、以下の通りです。

| 型     | 符号    | 指数部   | 仮数部   | 総ビット数 |
| ------ | ------- | -------- | -------- | ---------- |
| double | 1ビット | 11ビット | 52ビット | 64ビット   |
| float  | 1ビット | 8ビット  | 23ビット | 32ビット   |

これらの数値のうち精度の上で重要になってくるのが、「仮数部」です。
仮数部が実質的な数値の桁数を決めています。

具体的には、double型の仮数部は52ビットですが、正規化によって省略される1ビット（隠しビット）を含めると実質53ビットの精度を持ちます。
これは10進数換算で約15〜17桁の有効数字に相当します。
そのため、$10^{16}$を超える整数を扱う場合、1の位まで正確に表現できない可能性が生じます。
表現するためのビットが足りない場合、コンピュータは数値を「一番近い表現可能な数値」に変換します。
この時生まれる、元の数値と変換後の数値の差が、「丸め誤差」です。

以上の理論を踏まえ、冒頭のコードでなぜWrong Answerが発生したのか、原因を特定します。

上のコードの問題点は、以下の部分です。

```java
long root = (long) Math.sqrt(maxB);
```

このコードでは、Math.sqrtでlong型maxBの平方根を計算し、計算結果をlong型にキャストしています。

Math.sqrtメソッドは引数にdouble型を要求するため、long型の値を渡すと暗黙的にキャストされます。
この時、戻り値もdouble型となるため、以下の2段階で誤差が生じる可能性があります。

1つ目は、キャスト時の情報欠落です。Math.sqrtメソッドでは、引数をdouble型へ変換します。long型の最大値は $ 10^{18} $ ほどであるため、引数が $ 10^{16} $ を超えていた場合、double型に変換された時点ですでに丸め誤差が発生してしまいます。

2つ目は、計算の過程で生じる浮動小数点演算誤差です。計算時に無限小数を有限のビット数に収める際に、ごく僅かな「丸め誤差」が発生してしまいます。

このような浮動小数点の精度限界を考慮していない実装であったため、テストコードでWrongAnswerが出たと推測されます。

## 浮動小数点数による誤差の具体例

では、実際にどの程度の数値で誤差が発生し、判定に影響が出るのかを検証してみます。

Javaのlong型の最大値付近の数値であり、$10^{16}$ を超える整数 $1,000,000,001^{2}$ を例に挙げます。

```java
long original = 1000000001L; // 元の平方根
long n = original * original; // 元の整数 1000000002000000001L (約10^18)

double doubleN = (double) n; //doubleにキャスト
long result = (long) Math.sqrt(doubleN); //平方根を求めて、longにキャストする

System.out.println("元の平方根        : " + original);
System.out.println("元の整数 (n)      : " + n);
System.out.println("doubleにキャスト後 : " + String.format("%.1f", doubleN));
System.out.println("Math.sqrt結果     : " + Math.sqrt(doubleN));
System.out.println("計算結果をキャスト : " + result);
System.out.println("元の平方根との誤差  : " + (original - result));

//結果
//元の平方根         : 1000000001
//元の整数 (n)       : 1000000002000000001
//doubleにキャスト後  : 1000000002000000000.0
//Math.sqrt結果      : 1000000000.9999999
//計算結果をキャスト後 : 1000000000
//元の平方根との誤差   : 1
```

この例では、期待される平方根「1000000001」に対して、計算結果は「1000000000」となり、「1」の誤差が生じています。

まず、long型の整数nをdouble型にキャストした時点で下位の位が丸められ、Math.sqrtの計算過程でさらに誤差が発生しています。

その結果、本来「1000000001.0」となるべき戻り値が「1000000000.9999999...」となり、これをlong型にキャスト（小数点以下切り捨て）したことで、元の平方根より1小さくなってしまったのです。

## 丸め誤差の対策

精密な値を必要とする業務では、こういった丸め誤差を防ぐための対策が必要となります。
Java言語で代表的なのが、BigDecimalの利用です。

double型の内部では2進数で数値を扱いますが、BigDecimalは10進数表現をそのまま保持して計算を行います。
そのため、誤差のない厳密な計算が可能で、桁数もメモリが許す限り上限がありません。
その一方で、厳密性と引き換えに、浮動小数点の計算より計算速度が遅く、メモリ消費量が多いというトレードオフが存在します。
計算効率より厳密性が求められるお金の計算などには、BigDecimalの利用が推奨されます。

また、IDなど、計算の必要のない大きな桁の整数を扱う場合は、桁の上限がある数値型でなく、桁の上限がないString型として格納することも有効です。

## 苦戦した問題への対応

原因がわかったところで、コードを改善していきます。

実務では、BigDecimalにリファクタリングすることが望ましいでしょう。
しかし、今回は計算効率を重視する競技プログラミングの問題なので、double型のままで精度補正のコードを追加していきます。

```java
//修正後のコードです

import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        long n = scanner.nextLong();
        scanner.close();

        long goodNumberTotal = 0;
        long powerOf2 = 2;
        while (powerOf2 <= n) {
            long maxB = n / powerOf2;
            long root = (long) Math.sqrt(maxB);
            
            //精度補正用の追加コード ここから
            if ((root + 1) * (root + 1) <= maxB) {
                root++;
            }
            if (root * root > maxB) {
                root--;
            }
            //精度補正用の追加コード ここまで
            
            goodNumberTotal += (root + 1) / 2;
            
            if (n / 2 < powerOf2) {
              break;
            } else {
              powerOf2 *= 2;
            }
        }
        System.out.println(goodNumberTotal);
    }
}
```

追加コードのロジックを説明します。

浮動小数点数の誤差は極めて微小であるため、long型の変数rootの時点での誤差は±１の範囲と仮定されます。
そこで、得られた整数rootの近傍を整数演算で再検証するアプローチを採りました。

```java
//rootが真の値より小さすぎる場合
if ((root + 1) * (root + 1) <= maxB) root++;
```

1つ上の整数 (root+1) を2乗してもまだmaxB以下になる場合は、真の値はroot＋1以上であるはずなので、rootをインクリメントします。

```java
//rootが真の値より大きすぎる場合
if (root * root > maxB) root--;
```

rootを2乗した結果がmaxBより大きいなら、真の値はrootより小さいはずなので、rootをデクリメントします。

2乗する方法を採用した理由は、整数の乗数計算であれば、整数範囲で値が完結するため、数学的に厳密な計算ができると考えたためです。

これらの補正用コードを追加した状態で、無事「AC(正解)」判定がでました。

補足：今回は n <= $ 10^{18} $ という制約があったため問題になりませんでしたが、大きな値を扱う場合は (root + 1) * (root + 1) の結果がオーバーフローする可能性もあるため、注意が必要です。
