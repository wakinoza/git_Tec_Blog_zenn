## 1\. アノテーションとは

JUnitを用いたテスト開発では、テストの制御に「アノテーション」を利用します。

アノテーションとは、データの扱い方を示す「メタデータ」の一種です。

通常のソースコードは、処理方法など具体的に「何をするか」を記述しています。
一方、アノテーションは、記述されたソースコードを「外側からどう扱うか」をJUnitに伝えています。

テスト情報を、ソースコードに直接書かず、メタデータとして付与することには、2つの利点があります。

1つ目は、「関心の分離」です。
もしアノテーションが利用できなければ、ソースコード本体にテストコードを書く必要があります。その結果、本来記述したいビジネスロジックに、本番環境では不要なテストコードを混入させてしまうことになります。せっかく、テストが完了しても、テストコードを削除するとコードが動かなくなるような事態が発生しかねません。
ソースコードにテスト情報を書かず、アノテーションで情報を付与する形をとることで、ソースコードにテストコードが混入する事態を防いでいるのです。

2つ目は、振る舞いの切り替えです。
アノテーションはメタデータであるため、それらの情報がなくてもソースコードは問題なく動きます。そのため、テスト環境ではアノテーション情報を利用して、本番環境ではアノテーション情報を無視するというように振る舞いを切り替えることが可能になります。

## 2\. アノテーションの説明

次に、具体的なアノテーションについて説明していきます。

| アノテーション     | 説明                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| @Test              | このメソッドが、テストメソッドであることを示しますが、どのようなテストであるかは宣言しません。このメソッドは、オーバーライド されない限り、継承されます。                                                                                                                                                                                                                          |
| @ParameterizedTest | このメソッドが、パラメーター化テストであることを示します。このメソッドは、オーバーライド されない限り、継承されます。                                                                                                                                                                                                                                                              |
| @RepeatedTest      | このメソッドが、繰り返しテスト のためのテストテンプレートであることを示します。このメソッドは、オーバーライド されない限り、継承されます。                                                                                                                                                                                                                                         |
| @TestFactory       | このメソッドが、動的テスト のためのテストファクトリであることを示します。このメソッドは、オーバーライド されない限り、継承されます。                                                                                                                                                                                                                                               |
| @TestInstance      | アノテーションを付与したテストクラスに対して、テストインスタンスのライフサイクル を設定するために使われます。このアノテーションは継承されます。                                                                                                                                                                                                                                    |
| @TestTemplate      | このメソッドが、テストケースのテンプレート であることを示します。このメソッドは、登録した プロバイダ が返す実行コンテキストの数に応じて、複数回呼び出されます。このメソッドは、オーバーライド されない限り、継承されます。                                                                                                                                                         |
| @DisplayName       | 表示名を指定します。空白や特殊文字だけでなく絵文字も含めることができ、テストランナーやテストレポートに表示されます。このアノテーションは継承されません。                                                                                                                                                                                                                           |
| @BeforeEach        | このアノテーションが付与されたメソッドは、テストクラスの @Test, @RepeatedTest, @ParameterizedTest, @TestFactoryが付与されたメソッドが実行される前に、毎回実行されます。このメソッドは、オーバーライドされない限り、継承されます。                                                                                                                                                  |
| @AfterEach         | このアノテーションが付与されたメソッドは、テストクラスの @Test, @RepeatedTest, @ParameterizedTest, @TestFactoryが付与されたメソッドが実行された後に、毎回実行されます。このメソッドは、オーバーライドされない限り、継承されます。                                                                                                                                                  |
| @BeforeAll         | このアノテーションが付与されたメソッドは、テストクラスの @Test, @RepeatedTest, @ParameterizedTest, @TestFactoryが付与されたメソッドが実行される前に、１回だけ実行されます。通常は static である必要があります。ただし、@TestInstance(Lifecycle.PER_CLASS) を指定した場合は static でなくても実行できます。このメソッドは、隠ぺいするか、オーバーライドされない限り、継承されます。 |
| @AfterAll          | このアノテーションが付与されたメソッドは、テストクラスの @Test, @RepeatedTest, @ParameterizedTest, @TestFactoryが付与されたメソッドが実行された後に、１回だけ実行されます。通常は static である必要があります。ただし、@TestInstance(Lifecycle.PER_CLASS) を指定した場合は static でなくても実行できます。このメソッドは、隠ぺいするか、オーバーライドされない限り、継承されます。 |
| @Nested            | このクラスが、ネストした非staticのテストクラスであることを示します。このアノテーションは、継承されません。                                                                                                                                                                                                                                                                         |
| @Tag               | クラスまたはメソッドレベルでテストをフィルタリングするための タグ を宣言するのに使われます。このアノテーションは、クラスレベルでは 継承 されますが、メソッドレベルでは 継承 されません。                                                                                                                                                                                           |
| @Disabled          | テストクラスやテストメソッドを無効化するのに使われます。このアノテーションは、継承されません                                                                                                                                                                                                                                                                                       |
| @ExtendWith        | カスタムの 拡張機能 を登録するために使われます。このアノテーションは、継承されます。                                                                                                                                                                                                                                                                                               |

@Test, @TestTemplate, @RepeatedTest, @BeforeAll, @AfterAll, @BeforeEach, @AfterEach アノテーションが付与されたメソッドは、戻り値を返さないため、voidとなります。

## 3\. アサーションとは

アサーションとは、「期待値」と「実際の値」を比較するメソッドです。もし一致しなければ、例外を投げて、テストを失敗させます。開発者はアサーションの結果を確認することで、実際の値が期待通りであるかをチェックします。
アノテーションがテストの目印であれば、アサーションは実際の評価を担います。

@Test, @RepeatedTest, @ParameterizedTest, @TestFactoryが付与されたテストメソッドが起動している最中にのみ実行されます。
アサーションは、通常テストクラス内に記載されます。
標準的なビルドツール（MavenやGradle）の設定では、テストコードは本番用のビルド成果物から除外されるため、実行時のパフォーマンスやセキュリティに影響を与えることはありません。

また、すべてのJUnit Jupiterアサーションは、 org.junit.jupiter.api.Assertionsクラスのstaticメソッドです。static importしておくと、Assertions.assertEquals(...) とクラス名から書く手間を省け、テストコードの可読性を高めることができます。

## 4\. アサーション一覧

| メソッド                                  | 役割             | 説明                                                         |
| ----------------------------------------- | ---------------- | ------------------------------------------------------------ |
| assertEquals(exp, act)                    | 値の等価性       | 「期待値」と「実際の値」が等しいか検証します。               |
| assertNotEquals(exp, act)                 | 値の不一致       | 値が「等しくないこと」を検証します。                         |
| assertSame(exp, act)                      | 同一オブジェクト | インスタンスの参照先（メモリ上の位置）が同じか検証します。   |
| assertTrue(condition)                     | 真偽値（真）     | 結果が true であることを検証します。                         |
| assertFalse(condition)                    | 真偽値（偽）     | 結果が false であることを検証します。                        |
| assertNotNull(object)                     | 非ヌルチェック   | オブジェクトが null ではないことを検証します。               |
| assertThrows(Exception.class, executable) | 例外の発生       | 特定の例外が投げられることを検証します。                     |
| assertAll(executables...)                 | 一括検証         | 複数の検証をまとめます。途中で失敗しても全項目を検査します。 |

### 4-1\. アサーションの記述例

アサーションを使ったコード例は以下の通りです。

```Java
// Assertions.クラスをstatic importしておく
import static org.junit.jupiter.api.Assertions.*;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import java.util.List;
import java.util.ArrayList;

class AssertionTest {

    @Test
    @DisplayName("基本のアサーションを試す")
    void testBasicAssertions() {
        String str1 = "JUnit";
        String str2 = "JUnit";
        String str3 = new String("JUnit");
        
        // 値の比較
        assertEquals("JUnit", str1, "値が一致するはず");
        
        // インスタンスの比較
        assertSame(str1, str2, "文字列リテラルなので同じ参照");
        assertNotSame(str1, str3, "newしているので異なる参照");
        
        // 真偽値
        assertTrue(10 > 5);
        assertFalse(10 < 5);
    }

    @Test
    @DisplayName("Nullと例外のテスト")
    void testNullAndException() {
        Object obj = null;
        //nullであるかの検証
        assertNull(obj);

        List<String> list = new ArrayList<>();
        //nullでないことの検証
        assertNotNull(list);

        // 例外のテスト：0で割るとArithmeticExceptionが発生することを検証
        ArithmeticException exception = assertThrows(ArithmeticException.class, () -> {
            int result = 10 / 0;
        });

        // 発生した例外のメッセージをさらに詳しく検証できる
        assertEquals("/ by zero", exception.getMessage());
    }

    @Test
    @DisplayName("assertAllでまとめて検証する")
    void testGroupedAssertions() {
        //複数のテストをまとめて実行する。
        // 1つが失敗しても、残りの検証もすべて実行して結果を出してくれる
        assertAll("複数の検証",
            () -> assertEquals(2, 2),
            () -> assertEquals(10, 3 + 7),
            () -> assertEquals(5, 10 / 2)
        );
    }
}
```

### 4-2\. 検証失敗時の文字列

testBasicAssertions()メソッドのアサーションのコード例を見ると、アサーションの引数に文字列が渡されています。
この第3引数の文字列は、テストが失敗したときに表示される文字列です。

テストが失敗した際に、JUnitはもちろんエラーを表示してくれます。
エラーは以下のように表示されます。

```Plain
<!-- JUnitのエラーメッセージ例(文字列なし)-->
AssertionFailedError: Expected: 10, Actual: 8
```

しかし、CI/CDなどで多数のテストを同時に実行すると、このエラーがどのメソッドに由来するのか、どこの仕様が間違っているのか、を直感的に理解しにくいケースがあります。
そこで、このアサーションが何を検証しているのかを文字列で明示します。

```Plain
<!-- JUnitのエラーメッセージ例(文字列あり)-->
AssertionFailedError: 【エラー】在庫数の計算結果が設定値と一致しません。 ==> expected: <10> but was: <5>
```

失敗時に表示する文字列をアサーションメソッドに渡すことで、テスト結果の検証を効率的に行うことができるのです。

### 4-3\. JUnit5とラムダ式

また、assertThrowsやassertAllのアサーションのコード例を見ると、メソッド内でラムダ式が用いられています。
JUnit 5（Jupiter）では、アサーションの引数にラムダ式（Executableインターフェースや Supplierインターフェース）を渡すことができます。
ラムダ式は、assertThrowsのコード例のような例外の検証やassertAllのコード例のように複数のテストを一括で検証する際に用いられます。
その他の利用方法としては、失敗メッセージの生成などがあります。

```Java
@Test
@DisplayName("メッセージの遅延評価")
void testLazyMessage() {
    int actual = 10;
    int expected = 20;

    // メッセージを直接書かず、ラムダ式にする
    assertEquals(expected, actual, () -> "期待値は " + expected + " ですが、実際は " + actual + " でした");
}
```

上のようにラムダ式を用いることで、メッセージの生成が「遅延評価（Lazy Evaluation）」されます。テストが失敗したときのみ計算・生成されるため、特に複雑な文字列結合を伴う場合にリソースを節約できます。

## まとめ

- アノテーションによる関心の分離: メタデータを利用してテスト制御をビジネスロジックから分離することで、本番コードの純粋性を保ちつつ柔軟なテスト実行を可能にする。

- JUnit 5のモダンな検証: assertThrows による型安全な例外検証や assertAll による一括検証を活用し、テストの厳密さとデバッグ効率を両立させる。

- ラムダ式による最適化: ラムダ式を用いた遅延評価により、テスト失敗時のみメッセージ生成を行うなど、リソース効率と可読性を向上させる。

- 保守性の高いテスト設計: 失敗時のメッセージを明示することで、CI/CD環境下でも原因特定が容易になる。
