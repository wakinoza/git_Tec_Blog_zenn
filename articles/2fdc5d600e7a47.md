## はじめに

- AWS SOAの取得を目指して勉強中です。
- 間違い等あれば、指摘いただけると助かります。

## 結論

- MRAPは、複数リージョンに配置されたS3バケットへ、1つのグローバルエンドポイントからアクセスするための仕組みです。

- MRAPはリクエストを受信すると、オブジェクトがどのバケットに存在するかを確認するのではなく、近接性を考慮して、アクティブなリージョンのS3バケットへリクエストをルーティングします。

- そのため、あるリージョンにオブジェクトを作成した直後に別のリージョンへGetがルーティングされると、Get先のS3バケットにまだオブジェクトが存在せず、404(Not Found)になる可能性があります。

- この問題に対応するため、MRAPに関連付けたS3バケットにCRRを設定し、複数リージョンのバケットへオブジェクトをレプリケーションします。

- ただし、CRRは非同期レプリケーションであるため、あるリージョンで作成・変更されたオブジェクトが、他のリージョンへ即座に反映されるとは限りません。したがって、レプリケーションが完了する前に別のリージョンへGetがルーティングされると、404エラーが発生する可能性があります。


## 1\. MRAPとは

あるアカウントが、複数のリージョンにS3バケットを配置していたとします。
そのうち1つのS3バケットにリクエストを送る場合でも、ユーザーの所在地によって、最適なリージョンは異なります。
もし、ユーザーから地理的に離れたリージョンへリクエストを送ると、ネットワークレイテンシーが大きくなる可能性があります。

そこで、S3 Multi-Region Access Point（MRAP）を利用します。
MRAPは、複数のAWSリージョンに配置したS3バケットへ、1つのグローバルなエンドポイントからアクセスするための仕組みです。
グローバルエンドポイントに送られたリクエストは、アクティブなルーティング状態にあるリージョンの中から、近接性を考慮して適切なリージョンへ自動的にルーティングされます。
そのため、ユーザーが個々のリージョンを意識する必要がなくなります。

例えば、あるアカウントが東京、米国、欧州の3つのリージョンにS3バケットを配置していたとします。

```
                    MRAP
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
       東京S3       米国S3      欧州S3
```

ユーザーは、それぞれのS3バケットを個別に指定するのではなく、MRAPのグローバルエンドポイントへリクエストを送信します。
MRAPは、アクティブなリージョンの中から、近接性を考慮したリージョンへリクエストをルーティングします。

```
ユーザー
   │
   ▼
MRAPのグローバルエンドポイント
   │
   ▼
適切なリージョンのS3バケット
```

グローバルエンドポイントという共通の窓口に送るだけで、アクティブなリージョンの中から、近接性を考慮して適切なリージョンへMRAPが自動的にリクエストを転送します。

### 1\.1 AWS Global Accelerator

MRAPへのリクエストは、`AWS Global Accelerator`を利用してAWSグローバルネットワークへルーティングされます。

`AWS Global Accelerator`は、ユーザーからAWSへの通信をAWSのグローバルネットワークを利用することで、ネットワーク経路を最適化するサービスです。

MRAPでは、この仕組みを利用して、ユーザーからS3への通信を最適化しています。

### 1\.2リージョン障害への対応

また、MRAPはリージョン障害時の対応にも利用できます。

MRAPにはFailover Control（フェイルオーバー制御）があり、リージョン間でトラフィックを切り替えられます。
例えば、リージョン障害などによって利用するリージョンを切り替える必要がある場合、Failover Controlを利用して、トラフィックのルーティング先を別のリージョンへ切り替えることができます。



## 2\. MRAPはオブジェクトの存在場所を考慮してルーティングしない

MRAPは、複数のリージョンのうち、近接性を考慮して適切なリージョンへリクエストを自動的にルーティングする仕組みです。
しかし、MRAPは、リクエストをルーティングする際に、リクエスト対象のオブジェクトがどのバケットに存在するかを確認して、ルーティング先を決定するわけではありません。

そのため、あるリージョンに保存したデータをGetしようとした場合でも、Get先のリージョンにオブジェクトが存在せず、エラーが発生する場合があります。



具体的に説明しましょう。

MRAPを利用して、あるファイルをS3バケットに保存したとします。

その時点での近接性に基づいて、MRAPはリージョンAにリクエストを転送しました。
その結果、ファイルはリージョンAのS3バケットに格納されます。

その後、ユーザーが同じファイルをGetするリクエストを送ったとします。
このとき、MRAPはGetリクエストを、その時点で近接性の高いリージョンBへルーティングする可能性があります。

しかし、求めるファイルはリージョンAにあり、リージョンBにはありません。
求めるファイルが見つけられなければ、404(Not Found) エラーとなります。


## 3\. Amazon S3 クロスリージョンレプリケーション

MRAPを利用して、どのリージョンにリクエストがルーティングされても同じオブジェクトを取得できるようにするには、各リージョンのS3バケットにオブジェクトをレプリケーションしておく必要があります。

そこで利用するのが、Amazon S3 Cross-Region Replication（CRR）です。

CRRは、設定したレプリケーションルールに基づいて、S3オブジェクトを別のAWSリージョンにあるS3バケットへ非同期にレプリケーションする機能です。

例えば、リージョンAにオブジェクトを追加したとします。
CRRのレプリケーションルールを設定している場合、リージョンAに追加されたオブジェクトは、ルールで指定したリージョンB、リージョンCのバケットへ自動的にレプリケーションされます。

その結果、対象オブジェクトのCRRが各リージョンで完了していれば、MRAPによってどのリージョンへリクエストがルーティングされても、対象のオブジェクトを取得できるようになります。


##  4\. CRRを設定しても404が発生する可能性がある

ただし、CRRで注意する必要があるのが、レプリケーションは非同期であることです。

そのため、あるリージョンにオブジェクトを作成した直後に、別リージョンにGetリクエストが転送されたとしても、別リージョンへのCRRが完了していない段階であれば、対象オブジェクトは存在せず、404 (Not Found) エラーになる可能性があります。
CRRは、即時にレプリケーションされるわけではないため、404エラーが完全になくなるわけではありません。

このように、MRAPとCRRを組み合わせる場合は、CRRの非同期性によってリージョン間で一時的にデータの状態が異なる可能性があることを考慮する必要があります。

##  5\. S3 Replication Time Control

MRAPでのレプリケーション性能を高める方法として、S3 Replication Time Control（S3 RTC）があります。
S3 RTCは、CRRなどのレプリケーションルールに対して設定できる機能であり、新規オブジェクトの99.99%を15分以内にレプリケーションするSLAを提供しています。

ただし、S3 RTCを利用しても即時レプリケーションになるわけではありません。
そのため、レプリケーションが完了する前にGetリクエストが別リージョンへルーティングされれば、404エラーが発生する可能性があります。

S3 RTCはあくまで、レプリケーション時間を予測可能にするための仕組みです。

AWS公式ドキュメントでも、MRAPでのレプリケーション性能向上策としてS3 RTCの利用を推奨しています。



## まとめ

MRAPとCRRを理解するうえで重要なのは、両者の役割を分けて考えることです。

MRAP

- 複数リージョンのS3バケットへ1つのグローバルエンドポイントからアクセスする
- リクエストを近接性に基づいて適切なリージョンへルーティングする
- AWS Global Acceleratorを利用してAWSグローバルネットワークへリクエストを送る
- Failover Controlによってリージョン間のトラフィックを切り替えられる

CRR

- S3オブジェクトを別リージョンへレプリケーションする
- レプリケーションは非同期である
- そのため、あるリージョンに作成された直後のオブジェクトが、他のリージョンにまだ存在しない場合がある

MRAPは、オブジェクトが存在するリージョンを検索してからリクエストを送る仕組みではありません。
そのため、MRAPで複数リージョンのS3に保存された同じオブジェクトを、どのリージョンからでも取得できるようにする場合は、CRRによって各リージョンにオブジェクトをレプリケーションしておくことが重要です。

ただし、CRRは非同期であるため、レプリケーションが完了するまでの間に別リージョンへGetがルーティングされると、対象オブジェクトが存在せず404になる可能性があります。

したがって、MRAPとCRRを組み合わせても、404を完全になくせるわけではありません。
