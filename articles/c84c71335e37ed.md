## 1\. 環境変数とinit.sqlを利用したMySQL初期処理の実現

Webアプリケーションのログイン機能に、MySQLを利用しているとします。

WebアプリをGitHub上でDockerで簡単に実行できる環境を整えたいですが、Dockerを起動するたびにMySQLのテーブル作成や初期値投入をコマンドで実行するのは面倒ですし、ミスの元です。

そこで、環境変数とinit.sqlを利用して、MySQLのデータベース・テーブル、作業用ユーザ作成と初期値入力まで、まとめてDockerにお願いすることにしました。

自動化の対象範囲は、以下の通りです。

1. ルートパスワードの設定
2. データベースの作成
3. 作業用ユーザの設定
4. 作業ユーザのパスワードの設定
5. テーブルの作成
6. テーブルに初期値を入力

### 1-1\. 環境変数を用いた初期処理

上の項目のうち、ルートパスワードから作業用ユーザのパスワードの設定は、Docker composeの「environment」で設定できます。
「environment」でルートパスワード、データベース名、作業用ユーザ、作業用ユーザのパスワードを指定する方法は以下の通りです。

```compose.yml
services:
  db:
    image: mysql:8.4
    container_name: app-db
    environment:
      - MYSQL_ROOT_PASSWORD=root_password
      - MYSQL_DATABASE=db_name
      - MYSQL_USER=user_name
      - MYSQL_PASSWORD=user_password
    volumes:
      - db_data:/var/lib/mysql
    command:
      --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci

volumes:
  db_data:
```

「MYSQL_ROOT_PASSWORD」は、最上位の権限を持つrootユーザのパスワードを指定します。
MySQL公式Dockerイメージの仕様上、rootユーザのパスワード指定が必須です。指定しなければ、エラーとなりMySQLが起動できません。

「MYSQL_DATABASE」は、利用するデータベースの名前を指定します。この変数を指定すると、イメージ起動時に、指定されたデータベースが自動で作成されます。

「MYSQL_USER」「MYSQL_PASSWORD」は作業用ユーザのユーザ名とそのパスワードを指定します。
rootユーザは最上位の権限を持つ重要なユーザであるため、通常の業務には、別の作業用ユーザを作って利用します。通常の作業は作業用ユーザで、緊急時や重要な処理の時のみrootユーザを利用します。
「MYSQL_DATABASE」が指定されていると、指定された作業用ユーザにはデータベースに対するすべての権限（GRANT ALL）が自動で付与されます。

つまり、「environment」で変数を指定することで、以下のコマンドを実行したのと同様の状態になります。

```SQL
CREATE DATABASE db_name;
CREATE USER user_name@'%' IDENTIFIED BY 'user_password';
GRANT ALL PRIVILEGES ON db_name.* TO 'user_name'@'%';
```

### 1-2\. init.sqlを利用したMySQL初期処理

残るテーブル作成と初期値の入力は、環境変数ではできません。
そこで利用するのが、「init.sql」ファイルです。

MySQL公式イメージは、コンテナ起動時に「/docker-entrypoint-initdb.d」というフォルダの中にある、指定された拡張子のファイルを自動的に実行する仕組みが組み込まれています。
自動実行される拡張子には、「.sql」「.sh」「.sql.gz」「.sql.bz2」「.sql.xz」 「.sql.zst」などがあります。
SQLファイルを配置したディレクトリをマウントすることで、起動時に一括実行されます。

init.sqlの例は、以下の通りです。
（ログインパスワードは、本来ハッシュ化が必要ですが、このコードでは省略しています）

```SQL:init.sql
-- テーブルの作成（ログイン認証用）
CREATE TABLE IF NOT EXISTS users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    password VARCHAR(100) NOT NULL UNIQUE
);

-- userテーブルの初期値を入力
INSERT INTO users (name, password)
VALUES ('default_user','default_user_password')
ON DUPLICATE KEY UPDATE name=VALUES(name);
```

また、init.sqlをコンテナ内の指定されたフォルダへコピーする必要があります。
DockerfileのCOPYコマンドでも可能ですが、それではイメージに初期処理を含める設計になってしまいます。
イメージのポータビリティを保つため、初期処理はイメージに内包せず、Docker Composeのボリュームマウントを利用してコンテナ実行時に供給します。

以下は、compose.ymlにvolumesでinit.sqlファイルをマウントしているコード例です。

```yml：compose.yml
services:
  db:
    image: mysql:8.4
    container_name: app-db
    environment:
      - MYSQL_ROOT_PASSWORD=root_password
      - MYSQL_DATABASE=db_name
      - MYSQL_USER=user_name
      - MYSQL_PASSWORD=user_password
    volumes:
      - db_data:/var/lib/mysql
      # 以下のコマンドを追記
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql

volumes:
  db_data:
```

なお、init.sqlの自動読み込みは、「データディレクトリが空の時のみ」実行される仕様です。
そのため、一度起動してデータが作成された後は、init.sql を書き換えても反映されません。
設定を再反映させる場合は、「docker compose down -v」でボリュームを削除してから再度起動する必要があります。

これで、MySQLの初期設定をDockerに任せる設定が完了しました。

## 2\. .envを利用した、機密情報のGit管理除外方法

上記の記述は、MySQLの初期設定を自動化できていますが、セキュリティ上の問題があります。
それは、compose.ymlにMySQLのrootパスワード等の機密情報がそのまま記載されている点です。

このcompose.ymlをGitで管理しGitHubでチームで共有すると、機密情報がリポジトリ経由で共有・公開されてしまいます。

そこで、Gitに管理されない（.gitignoreに追加）.envファイルという別ファイルを作成し、機密情報をこのファイルに分離します。

「.env」ファイルの記述方法は、以下の記事の「5. .envの記載」という項目に説明されています。

https://zenn.dev/wakinoza/articles/991cfc8b0f539c

.envファイルを作成した状態が以下の通りです。

```.env
MYSQL_ROOT_PASSWORD=root_password
MYSQL_DATABASE=db_name
MYSQL_USER=user_name
MYSQL_PASSWORD=user_password
```

```.env.example
MYSQL_ROOT_PASSWORD=
MYSQL_DATABASE=
MYSQL_USER=
MYSQL_PASSWORD=
```

```yml：compose.yml
services:
  db:
    image: mysql:8.0
    container_name: app-db
    # 以下のコマンドを追記
    env_file:
      - .env
    environment:
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
      - MYSQL_DATABASE=${MYSQL_DATABASE}
      - MYSQL_USER=${MYSQL_USER}
      - MYSQL_PASSWORD=${MYSQL_PASSWORD}
    volumes:
      - db_data:/var/lib/mysql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql

volumes:
  db_data:
```

## 3\. Dockerの実行方法

作成したアプリのディレクトリは以下のようになっているとします。
（今回は、MySQLの設定に焦点を当てているため、ソースコードやTomcat、Mavenの設定についての説明は省略しています）

```Plain
root
├── src              # Webアプリのソースコード
├── compose.yml      # Dockerコンテナ構成定義
├── Dockerfile       # Tomcatイメージのビルド定義
├── context.xml      # Tomcat環境設定
├── init.sql         # DB初期処理
├── pom.xml          # Maven依存関係管理
├── .env             # 環境変数管理(Git管理外)
├── .env.example     # 環境変数テンプレート
└── .gitignore       # Git管理除外設定
```

ディレクトリをGitHubに公開すると、Git管理から外れている「.env」 を除外した以下のディレクトリ構造が確認できると思います。

```Plain
root
├── src              # Webアプリのソースコード
├── compose.yml      # Dockerコンテナ構成定義
├── Dockerfile       # Tomcatイメージのビルド定義
├── context.xml      # Tomcat環境設定
├── init.sql         # DB初期処理
├── pom.xml          # Maven依存関係管理
├── .env.example     # 環境変数テンプレート
└── .gitignore       # Git管理除外設定
```

このディレクトリをクローンして手元の環境で実行してみましょう。

1. リポジトリをクローン
```bash
git clone [GitHubのリポジトリのURL]
cd [GitHubのリポジトリ名]
```

2. 環境変数の準備 .env.example をコピーして .env を作成し、必要な値を設定する。
```bash
cp .env.example .env
```

```.env
MYSQL_ROOT_PASSWORD=root_password
MYSQL_DATABASE=db_name
MYSQL_USER=user_name
MYSQL_PASSWORD=user_password
```

各項目に適切な値を記述します。
初心者で注意してほしいのが、もし手元の環境にMySQLがありすでにrootパスワードを設定してあったとしても、「.env」のMYSQL_ROOT_PASSWORDにあなたのrootパスワードを記述する必要はないという点です。

Dockerコンテナは、ホスト環境とは独立した環境を構築するシステムです。そのため、
Dockerコンテナでこれから構築するMySQLは、あなたの環境のMySQLとは、まったく別のシステムです。
別のシステムなので、rootパスワードも別のものを利用します。


3. rootディレクトリに移動し、コンテナの起動
```bash
docker compose up -d --build
```

これでアプリが実行されます。ログイン画面に出たら、先ほどinit.sqlで入力したユーザ名とパスワードを入力すると、ログインできるはずです。

## まとめ

- MySQL初期化の自動化: docker-entrypoint-initdb.d に init.sql をマウントすることで、コンテナ起動時のDB・テーブル作成、初期値投入を自動化。

- 機密情報の分離: .env ファイルと env_file 指定を活用し、パスワード等の機密情報をコードから切り離し、安全に GitHub へ公開できる。
