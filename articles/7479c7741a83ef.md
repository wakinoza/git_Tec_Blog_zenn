## はじめに

- AWSのデプロイ作業を行う際に、`sftp`コマンドをよく利用しています。
- この記事では、`SFTP`プロトコルと`sftp`コマンドについてまとめています。
- 間違い等あれば、指摘いただけると助かります。

## 結論

- `SFTP（SSH File Transfer Protocol）`は、`SSH`上で動作する安全なファイル転送プロトコルです。
ファイル転送だけでなく、ディレクトリ作成・削除、ファイル名変更、権限変更などの操作も行えます。
- `sftp`コマンドでは、`get`・`put`によるファイル転送に加えて、`ls`・`cd`・`mkdir`・`chmod`などのリモート操作と、`lcd`・`lls`・`lpwd`などのローカル操作を行えます。
- `SFTP`は`SSH`の暗号化・認証基盤を利用し、通常はTCP 22番ポートを使用するため、ファイアウォールなどのネットワーク設定を比較的シンプルにできます。
- OpenSSH 9.0以降では、`scp`コマンドもデフォルトで`SFTP`プロトコルを使用してファイル転送を行います。


## 1\. SFTPとは

`SFTP（SSH File Transfer Protocol）`は、リモートサーバーとのファイル転送やファイル・ディレクトリ操作を行うためのプロトコルです。
具体的には、以下のような操作が可能です。

- ローカル-リモート間のファイル転送
- ファイルやディレクトリの作成・名前変更・一覧表示・削除
- アクセス権限の変更
- シンボリックリンクの作成
- ファイル転送中に中断が発生した場合に、転送を再開できる機能

`SFTP`は、`SSH（Secure Shell）`上で動作します。

`SSH`は、ネットワーク経由でリモートサーバーを安全に操作するためのプロトコルです。
SSH接続では、通信内容が暗号化されるため、第三者による通信内容の盗聴を防ぐことができます。
また、パスワード認証や公開鍵認証などの認証方式を利用できます。

`SFTP`は、`SSH`による暗号化通信や認証の仕組みを利用しているため、安全にファイル転送やファイル操作を行うことができます。


## 2\. 他プロトコルとの比較

`SFTP`を理解するために、ここでは`telnet`・`FTP`・`SCP`・`FTPS`との違いを説明します。

### 2\.1 telnet・FTP

`telnet`と`FTP（File Transfer Protocol）`は、古くから利用されてきたネットワークプロトコルです。

`telnet`は、ネットワーク越しにリモートサーバーへ接続し、文字ベースでコマンド操作を行うプロトコルです。

`FTP`は、異なるコンピュータ間でファイルをやり取りするためのプロトコルです。

通常の`telnet`と`FTP`には、通信内容を暗号化する仕組みがありません。
認証情報や通信内容が平文で送信されてしまうため、第三者に盗聴されるリスクがあります。

そのため、インターネットなどの信頼できないネットワーク上では`Telnet`や`FTP`ではなく、`SSH`や`SFTP`、後述する`FTPS`などの暗号化されたプロトコルを利用することが一般的です。


### 2\.2 SFTPとSCPの違い

`SSH`を利用したファイル転送プロトコルには、`SFTP`と`SCP（Secure Copy Protocol）`があります。

従来の`SCP`プロトコルは、ファイル転送に特化した仕組みで、`SFTP`のようなファイル操作機能やレジューム機能はありません。

`SCP`は、過去に複数のセキュリティ脆弱性（CVE-2019-6111 や CVE-2020-15778 など）が発見されたため、OpenSSHでは、`SCP`プロトコルの利用を避ける方向で仕様が変更されています。

互換性のため、OpenSSHでは現在も`scp`コマンドは提供されています。
しかし、OpenSSH 9.0以降では、`scp`コマンドによるファイル転送には内部で`SFTP`プロトコルがデフォルトで使用されています。


### 2\.3 SFTPとFTPSの違い

`FTP`にSSL/TLS暗号化を追加し、安全に通信を行えるようにしたプロトコルが`FTPS（FTP Secure / FTP over SSL/TLS）`です。

`SFTP`と`FTPS`は、どちらもリモートサーバーとのファイルのやり取りを安全に行うためのプロトコルです。
しかし、ベースとなる暗号化技術、通信ポート、データ形式などに違いがあります。

1. 暗号化技術
  `SFTP`は`SSH`の暗号化・認証基盤を利用して動作するプロトコルです。
  パスワード認証や公開鍵認証などを利用できます。
  一方の`FTPS`は、伝統的な`FTP`をベースに、SSL/TLS証明書を用いて通信を保護します。
  ユーザー名・パスワードによる認証に加えて、TLSのクライアント証明書を利用した認証などが可能です。
  また、`FTPS`ではTLS証明書を利用してサーバーの身元を確認できます。
2. 通信ポート
  `SFTP`は、`SSH`上で動作し、通常はTCPポート22番を使用します。
  一方の`FTPS`は、`FTP`と同様に制御用の接続とデータ転送用の接続を分けて使用します。
  そのため、`SFTP`と比較すると`FTPS`のほうが、ファイアウォールやNATなどのネットワーク設定が複雑になりやすいという特徴があります。
3. データ形式
  `FTPS`は`FTP`と同様に、ASCIIモードとバイナリモードの2種類のデータ形式を選択できます。
  一方の`SFTP`には、ASCIIモード／バイナリモードの切り替えはありません。
  そのため、`SFTP`ではファイルの内容をテキストとして解釈し、改行コードなどを自動的に変換する機能はありません。

`SFTP`と`FTPS`の違いは、以下の通りです。

| 特徴                   | SFTP                          | FTPS                                              |
| ---------------------- | ----------------------------- | ------------------------------------------------- |
| ベースとなるプロトコル | SSH                           | FTP                                               |
| 暗号化                 | SSH                           | TLS                                               |
| 主な認証               | パスワード、公開鍵認証など    | ユーザー名・パスワード、TLSクライアント証明書など |
| サーバー認証           | SSHホスト鍵                   | TLS証明書                                         |
| 通信方式               | SSH上で動作                   | FTP + TLS                                         |
| 接続ポート             | 通常はTCP22番ポート           | 制御接続とデータ接続を分離                        |
| データ転送モード       | ASCII／バイナリの切り替えなし | ASCIIとバイナリ                                   |

`SFTP`と`FTPS`はどちらも暗号化されたファイル転送を実現できますが、使用しているプロトコルや通信方式などが異なります。

特に、`SFTP`は、`SSH`上で動作し、通常は1つのSSH接続で通信できるため、`FTPS`と比べてネットワーク構成をシンプルにしやすいという特徴があります。

## 3\. SFTPの利点と欠点


### 3\.1 SFTPの利点

1. `SSH`による暗号化通信
  `SSH`によって通信が暗号化されるため、認証情報や転送データを暗号化して送信できます。
2. 豊富なファイル・ディレクトリ操作機能
  ファイルの送受信だけでなく、リモート環境でのディレクトリ作成・削除（`mkdir`/`rmdir`）、権限変更（`chmod`）、ファイル名変更（`rename`）などの操作が可能です
3. 転送中断時の再開（レジューム機能）
  OpenSSHの`sftp`コマンドでは、ネットワーク切断などで転送が中断した場合に、途中から転送を再開できます。
4. OpenSSHで利用できる
  `sftp`コマンドは、OpenSSHに標準で登録されています。Linux、macOS、Windows 10/11などはOpenSSHクライアントを利用できるため、OpenSSHがインストールされている環境であれば、追加のSFTP専用ソフトウェアを導入せずにCLIから利用できます。
5. 基本的な操作を共通のコマンドで行える
  SFTP接続後の基本コマンドは、Windows、macOS、Linuxなどで共通して利用できます。
6. 単一の接続で動作しネットワーク設定をシンプルにしやすい
  制御用とデータ用で複数ポートを使用する`FTPS`とは異なり、`SFTP`は通常、`SSH`の1つの接続上で通信するため、ネットワーク設定をシンプルにしやすい。

### 3\.2 SFTPの欠点

1. テキスト・改行コードの自動変換（ASCIIモード）がない
  `FTPS`では、テキストファイル転送時に改行コードなどを自動変換する「ASCIIモード」と「バイナリモード」を選択できます。一方、`SFTP`には`FTP`のようなASCIIモード／バイナリモードの切り替えはありません。そのため、OS間の改行コードの違いなどをプロトコル側で自動吸収する仕組みはありません。
2. 初期設定や鍵管理の手間
  公開鍵認証を利用する場合は、SSH鍵ペア（公開鍵・秘密鍵）の発行やサーバーへの登録、秘密鍵ファイルの権限設定（`chmod 600` 等）が必要となります。そのため、認証方式によっては初期設定や運用の手間がかかります。


## 4\. SFTPコマンドの利用方法

この章では、`SFTP`プロトコルを利用するための`sftp`コマンドの操作方法について説明します。

### 4\.1  SFTP接続

まずは、`SFTP`接続を行います。

接続時の認証は、「パスワード認証」と「公開鍵認証」の2つの方式が主に利用できます。
`SFTP`の認証は、`SFTP`独自の認証機構ではなく、`SFTP`が利用する`SSH`の認証機構によって行われます。

【パスワード認証】

`sftp`コマンドを実行すると、認証が行われます

```Bash
sftp [オプション] ユーザー名@ホスト名
```

例えば、ユーザー名がuser、ホスト名がexample.comの場合は、以下のように実行します。

```Bash
sftp user@example.com
```

`sftp`コマンドを実行した後、パスワードの入力を求められます。


【公開鍵認証】

公開鍵認証を利用する場合は、`-i`オプションで秘密鍵ファイルを指定します。
~/.ssh/に配置したid_ed25519という秘密鍵ファイルを認証に利用する場合は、以下のコマンドを実行します。

```Bash
sftp -i ~/.ssh/id_ed25519 user@example.com
```

公開鍵認証では、あらかじめクライアントが秘密鍵を保持し、サーバー側に対応する公開鍵を登録しておくことで認証を行います。


いずれかの認証に成功すると、`sftp`コマンドの対話型セッションが開始されます。

```Bash
sftp>
```


### 4\.2  ファイル転送

`SFTP`接続後は、対話型セッションでコマンドを実行します。

ローカルからリモートへファイルをアップロードする場合は、`put`コマンドを実行します。

例えば、ローカルの現在のディレクトリに存在するexample.txtを、リモートの現在ディレクトリへアップロードする場合は、以下のコマンドを実行します。

```sftp
put example.txt
```

転送先のリモートのディレクトリ（/remote/tmp/）を指定する場合は、以下のコマンドを実行します。

```sftp
put example.txt /remote/tmp/
```

逆に、リモートの現在のディレクトリに存在するexample.txtを、ローカルの現在ディレクトリへダウンロードする場合は、`get`コマンドを実行します。

```sftp
get example.txt
```

転送先のローカルのディレクトリ（/local/tmp/）を指定する場合は、以下のコマンドを実行します。

```sftp
get example.txt /local/tmp/
```

putとgetの関係は、以下のようになります。

```Plain
ローカル ── put ──→ リモート
ローカル ←─ get ── リモート
```

ディレクトリを再帰的に転送する場合は、`-r`オプションを利用します。

```sftp
put -r example/
get -r example/
```


### 4\.3  リモート操作の基本コマンド

対話型セッションでは、ファイル転送だけでなく、リモートサーバー上のファイルやディレクトリを操作できます。

リモート操作コマンドには、Linuxのシェルコマンドと同じ名前のものが多くあります。
一方、ファイル・ディレクトリ名の変更には`mv`ではなく`rename`、シンボリックリンクの作成には`ln -s`ではなく`symlink`を使用するなど、`sftp`コマンド独自の操作もあります。


主なリモート操作コマンドは以下の通りです。

| sftpコマンド | Linuxシェルで対応する操作 | 用途                               |
| ------------ | ------------------------- | ---------------------------------- |
| `pwd`        | `pwd`                     | 現在のディレクトリを表示           |
| `ls`         | `ls`                      | ファイル・ディレクトリを一覧表示   |
| `cd`         | `cd`                      | ディレクトリを移動                 |
| `mkdir`      | `mkdir`                   | ディレクトリを作成                 |
| `rmdir`      | `rmdir`                   | ディレクトリを削除                 |
| `rm`         | `rm`                      | ファイルを削除                     |
| `chmod`      | `chmod`                   | アクセス権限を変更                 |
| `chown`      | `chown`                   | 所有者を変更 （UIDを指定）         |
| `chgrp`      | `chgrp`                   | グループを変更 （GIDを指定）       |
| `rename`     | `mv`                      | ファイル・ディレクトリの名前を変更 |
| `symlink`    | `ln -s`                   | シンボリックリンクを作成           |
| `readlink`   | `readlink`                | シンボリックリンクの参照先を表示   |

なお、実際に利用できる操作は、サーバー側の権限や`SFTP`サーバーの実装・設定によって異なる場合があります。

### 4\.4  ローカル操作の基本コマンド


対話型セッションでは、接続先のリモートサーバーだけでなく、SFTPクライアント側のローカル環境も操作できます。

「`sftp`コマンドでローカル環境の操作が必要なの？」と疑問に思うかもしれません。

例えば、ローカル環境の複数のディレクトリに分散したファイルを、一度の`SFTP`接続でアップロードしたいとします。
`lcd`コマンドでローカル側のカレントディレクトリを変更できれば、`SFTP`接続を切断せずに異なるディレクトリのファイルを転送できます。

ローカル操作コマンドには、リモート操作と区別するために、コマンド名の先頭に`l`（local）が付くものが多くあります。

主なローカル操作コマンドは以下の通りです。

| sftpコマンド | Linuxシェルで対応する操作 | 用途                                         |
| ------------ | ------------------------- | -------------------------------------------- |
| `lpwd`       | `pwd`                     | ローカル側の現在のディレクトリを表示         |
| `lls`        | `ls`                      | ローカル側のファイル・ディレクトリを一覧表示 |
| `lcd`        | `cd`                      | ローカル側のディレクトリを移動               |
| `lmkdir`     | `mkdir`                   | ローカル側にディレクトリを作成               |


### 4\.5  レジューム

`reget`コマンドや`reput`を使用すると、中断した転送を途中から再開できます。

対話型セッションでは、ファイルの転送中に進捗が表示されます。

そのため、転送が最後まで完了しなかった場合は、進捗表示やエラーメッセージから、転送が完了していないことを確認できます。

以下は、ネットワークが切断され、転送が途中で終了した場合の表示例です。

```
sftp> get large-file.zip
Fetching /home/user/large-file.zip to large-file.zip
large-file.zip       45%  450MB  10.0MB/s   00:55 ETA
Connection closed
```

このような場合、転送先のローカル環境には、途中まで転送された部分ファイルが残ることがあります。
この「途中まで転送された部分ファイル」がある状態で、再び`get`コマンドを実行すると、転送の再開ではなく、ファイルを転送し直すことになります。

しかし、OpenSSHの `sftp`コマンドには、中断した転送を途中から再開するレジューム機能があります。
レジューム機能を使うと、「途中まで転送された部分ファイル」のサイズを基準に、ファイルの続きを取得できます。
これにより、すでに転送済みの部分を再度転送する必要がなく、無駄な通信を抑えられます。


リモートからローカルへのダウンロードを再開する場合は、`reget`コマンドを使用します。

例えば、example.zipのダウンロードが途中で中断した場合は、以下のコマンドを実行します。

```sftp
reget example.zip
```

逆に、ローカルからリモートへのアップロードを再開する場合は、`reput`コマンドを使用します。

```sftp
reput example.zip
```

`reget`と`reput`の関係は、以下のようになります。

```Plain
ローカル ←─ reget ─ リモート
ローカル ── reput ─→ リモート
```

ただし、レジューム機能は、「途中まで転送された部分ファイル」が転送元のファイルと対応していることが前提となります。
転送元のファイルが別のファイルに置き換わっていたり、内容が変更されたりした場合は、部分ファイルと転送元の内容が一致せず、転送後のファイルが破損する可能性があるため、注意が必要です。

### 4\.6  接続終了

対話型セッションでの操作が終了したら、 `quit`コマンドで対話型セッションを終了できます。

```sftp
quit
```

`quit`のほかに、`bye`や`exit`も接続終了できます。

```sftp
bye
exit
```
いずれのコマンドでもセッションが終了し、通常のシェルに戻ります。


## まとめ

* SFTPでは、接続先のサーバー側の権限や設定によって、利用できるファイル操作が異なる場合があります。必要な操作が利用できるか、事前に確認しておくことが重要です。

* レジューム機能を利用する場合は、転送元のファイルと途中まで転送された部分ファイルが同じものであることを確認する必要があります。転送元のファイルが変更されていると、転送後のファイルが破損する可能性があります。

* SFTPはSSH上で動作するため、ファイアウォールなどのネットワーク設定を比較的シンプルにできます。一方で、SSHの認証設定やアクセス制御など、SSH側のセキュリティ設定も適切に行う必要があります。
