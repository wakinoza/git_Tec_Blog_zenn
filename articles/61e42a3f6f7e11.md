## 1\. SQL命令の４つの分類

最初にSQL文の分類について説明します。
SQL文は多種存在しますが、大きく分けると４種類に分類できます。

| 名前                                                          | 種類                                           | 例                                      |
| ------------------------------------------------------------- | ---------------------------------------------- | --------------------------------------- |
| データ操作言語（DML：Data Manipulation Language）             | 値の格納や取り出し、更新、削除などの命令       | SELECT、INSERT、UPDATE、DELETEなど      |
| トランザクション制御言語（TCL：Transaction Control Language） | トランザクションの開始や終了の命令             | START TRANSACTION、COMMIT、ROLLBACKなど |
| データ定義言語（DDL：Data Definition Language）               | テーブルなどの作成や削除、各種設定などの命令   | CREATE、ALTER、DROPなど                 |
| データ制御言語（DCL：Data Control Language）                  | DMLやDDLの利用に関する許可や禁止を設定する命令 | GRANT、REVOKEなど                       |

この記事では、DDLについて説明していきます。

## 2\. データベースの作成・削除・変更

### 2-1\. CREATE DATABASE

MySQLでテーブルを作成する前に、まず「データベース」を作成します。
「データベース」とは、テーブルやビュー、インデックスなどを格納する「入れ物」のようなもので、「スキーマ」とほぼ同義として扱われます。

データベースを作成するには、「CREATE DATABASE」文の後に、任意のデータベース名（例として、db_nameとします）を指定します。
なお、「CREATE SCHEMA」も、「CREATE DATABASE」のシノニム（別名）として設定されています。

```SQL
--基本のデータベース作成文
CREATE DATABASE db_name;
```

「CREATE DATABASE」文でデータベースを作成する際、指定されたデータベース名がすでに存在している場合は、エラーとなります。
命令文に「IF NOT EXISTS」をつけると、指定されたデータベース名が存在しない場合のみ、データベースを作成します。もし、指定されたデータベース名がすでに存在する場合は、エラーは出ず、新規作成作業を行わずに命令を終了します。

また、任意でオプションを指定することで、データベースのデフォルト値を設定できます。
代表的なオプションは以下の通りです。

| オプション名  | 指定内容                           |
| ------------- | ---------------------------------- |
| CHARACTER SET | デフォルトのデータベース文字セット |
| COLLATE       | デフォルトのデータベース照合順序   |
| ENCRYPTION    | デフォルトのデータベース暗号化     |


「CHARACTER SET」は、文字のエンコーディングを定義します。デフォルトは「utf8mb4」となっています。「utf8mb4」は4バイトのUTF-8で、絵文字や特殊文字に対応しているため、モバイルアプリ・SNSのデータを利用するのに適しています。特別な理由がない限り、「utf8mb4」を利用することが一般的です。

「COLLATE」は文字をどのように比較・ソートするかを定義する設定です。MySQLで「CHARACTER SET」にutf8mb4を指定した場合、大文字・小文字やアクセント記号を区別しない「utf8mb4_0900_ai_ci」がデフォルトの照合順序となります。厳密な一致が求められる場合は、文字をバイナリとして比較する「utf8mb4_bin」も指定可能です。

「ENCRYPTION」を指定することで、データベース内のテーブルをデフォルトで「透過的データ暗号化（TDE）」を実行するかどうかを設定できます。
「透過的データ暗号化」は、データベース側で暗号化・複合を行うため、アプリケーション側でそれらのロジックを開発する必要がありません。また、万が一、ストレージなどが流出しても、暗号鍵がなければ複合できないため、データを保護できます。

オプションを指定するSQL文は以下の通りです。（[]で囲まれている命令文は、任意です）

```SQL
--オプションを指定したデータベース作成文
CREATE DATABASE [IF NOT EXISTS] db_name
    [DEFAULT CHARACTER SET = charset_name]
    [DEFAULT COLLATE = collation_name]
    [DEFAULT ENCRYPTION = {'Y' | 'N'}]
```

### 2-2\. DROP DATABASE

データベース内のすべてのテーブルを削除し、データベースそのものも削除する場合は、「DROP DATABASE」文の後に、削除したいデータベース名を指定します。
こちらも、「DROP SCHEMA」が「DROP DATABASE」のシノニム（別名）として設定されています。

```SQL
--基本のデータベース削除文
DROP DATABASE db_name;
```

「DROP DATABASE」文では、指定したデータベースが存在しない場合は、エラーとなります。
命令文に「IF EXISTS」をつけると、指定されたデータベース名が存在する場合のみ、データベースを削除します。もし、指定されたデータベース名が存在しない場合、エラーは発生せず、処理を行わずに終了します。

```SQL
DROP DATABASE [IF EXISTS] db_name;
```

「DROP DATABASE」文は、全データを即時削除する非常に強力な命令です。そのため、実務環境では、誤動作で「DROP」が実行されることがないような仕組みが設けられます。作業用ユーザーには「DROP」権限を与えないようにしたり、「DROP」文をコード内記述することを禁止するなどの運用が行われます。

### 2-3\. ALTER DATABASE

「CREATE DATABASE」で指定したデフォルト設定は、「ALTER DATABASE」で変更することができます。
こちらも、「ALTER SCHEMA」が、「ALTER DATABASE」のシノニム（別名）として設定されています。

```SQL
ALTER DATABASE db_name
    [DEFAULT CHARACTER SET = charset_name]
    [DEFAULT COLLATE = collation_name]
    [DEFAULT ENCRYPTION = {'Y' | 'N'}]
```

変更できるのは、デフォルト設定のみで、データベース名を後から変更することができません。

## 3\. テーブルの作成・削除・変更

次にテーブルを作成します。
MySQLにおいて、テーブルはデータベースに格納します。
そのためまず、新規作成するテーブルを格納するためのデータベースを「USE」文で指定します。

```SQL
USE db_name;
```

### 3-1\. CREATE TABLE

テーブルを作成するには、「CREATE TABLE」文の後に、任意のテーブル名（例として、table_nameとします）を指定します。

```SQL
--基本のテーブル作成文
CREATE TABLE table_name (
    列の情報１,
    列の情報２,
    …
)
```

「CREATE TABLE」文も、「CREATE DATABASE」文と同様に、指定されたテーブル名がすでに存在している場合は、エラーとなります。
命令文に「IF NOT EXISTS」をつけると、指定したテーブル名が存在しない場合のみ、データベース作成を実行します。もし、指定したテーブル名が既に存在する場合は、エラーは起きず、何もせずに命令は終了します。

また、テーブル作成時に「TEMPORARY」キーワードを使用できます。
TEMPORARYキーワードを使用したテーブルは、現在のセッション内でのみ表示され、セッションがクローズされると、自動的に削除されます。

さらに、任意でオプションを指定することで、テーブルのデフォルト値を設定できます。
代表的なオプションは以下の通りです。

| オプション名  | 指定内容                           |
| ------------- | ---------------------------------- |
| CHARACTER SET | デフォルトのデータベース文字セット |
| COLLATE       | デフォルトのデータベース照合順序   |
| ENGINE        | デフォルトのストレージエンジン     |
| COMMENT       | コメント情報                       |

「ENGINE」は「InnoDB」がデフォルトとなっています。「InnoDB」はACID準拠のトランザクションをサポートしており、行レベルのロックが可能であるため、高い同時実行性と信頼性を実現できます。現在は、特別な理由がない限り、デフォルトの「InnoDB」を利用するのが望ましいでしょう。

```SQL
--オプションを指定したテーブル作成文
CREATE [TEMPORARY] TABLE [IF NOT EXISTS] table_name (
    列情報１,
    列情報２,
    ……
)
[DEFAULT CHARACTER SET = charset_name]
[DEFAULT COLLATE = collation_name]
[ENGINE = engine_name]
[COMMENT = comment_string]
```

先ほどの命令文で「列情報」とした部分には、テーブルの列に関する情報を記述します。
コンマで区切られた1つのかたまりが1つの列を表し、必要な列数だけ列挙します。

列情報において必須なのは、「列名」と「データ型」の2つです。
「列名」は開発者が任意で作成することができます。データ型はMySQLで標準として用意されているものから選びます。
MySQLで用意されているデータ型については、以下の記事でまとめています。

https://zenn.dev/wakinoza/articles/37496150048e47

ユーザー情報を格納するテーブルを作成するSQL例文は以下の通りです。

```SQL
--テーブル作成例
CREATE TABLE users (
  id INTEGER,
  user_name VARCHAR(50),
  email VARCHAR(100),
  birth DATETIME
);
```

上の「CREATE TABLE」文は、以下のテーブルを作成しています。

| 列名      | データ型     | データ型の説明              |
| --------- | ------------ | --------------------------- |
| id        | INTEGER      | 整数型                      |
| user_name | VARCHAR(50)  | 最大50字までの可変長文字列  |
| email     | VARCHAR(100) | 最大100字までの可変長文字列 |
| birth     | DATETIME     | 日時時刻型                  |

列情報には他に、任意で「制約」を指定することができます。
制約については、後述します。

### 3-2\. DROP TABLE

テーブル定義とすべてのテーブルの値を削除する場合は、「DROP TABLE」文の後に、削除したいテーブル名を指定します。

```SQL
--基本のテーブル削除文
DROP TABLE table_name;
```

「DROP TABLE」文も、「DROP DATABASE」文と同様に、指定されたテーブル名が存在しない場合は、エラーとなります。
命令文に「IF EXISTS」をつけると、指定されたテーブル名が存在する場合のみ削除します。もし、指定されたテーブル名が存在しない場合も、エラーは起きず、何もせずに命令は終了します。

また、「TEMPORARY」キーワードを使用することで、削除対象をTEMPORARYテーブルのみに指定できます。

```SQL
DROP [TEMPORARY] TABLE [IF EXISTS] table_name;
```

「DROP TABLE」は実行するとテーブル内のデータと定義が即座に消去されるため、慎重に利用することが必要です。
実務現場では、不要になったテーブルを後述する「ALTER TABLE」でRENAMEしたり、後述する「外部キー」などの影響範囲をシミュレーションしてから適用するなど、誤操作によるデータ消失を防ぐ工夫が行われます。

### 3-3\. ALTER TABLE

作成したテーブル定義を変更する場合は、「ALTER TABLE」文を利用します。
「ALTER TABLE」でできることは、以下の通りです。

- カラムの追加・削除
- インデックスの作成・削除
- カラム・テーブルの名称の変更
- カラムのデータ型の変更
- ストレージエンジンやコメントの変更

例えば、「CREATE TABLE」で作成した usersテーブルにcountryカラムを追加したい場合は、以下の命令文を実行します。

```SQL
ALTER TABLE users
  ADD COLUMN country VARCHAR(50) AFTER user_name;
```

「AFTER user_name」という命令文で、新規カラムの挿入場所を、user_nameカラムの後と指定することができます。
上の「ALTER TABLE」文を実行した後のusersテーブル定義は、以下の状態になります。


| 列名      | データ型     |
| --------- | ------------ |
| id        | INTEGER      |
| user_name | VARCHAR(50)  |
| country   | VARCHAR(50)  |
| email     | VARCHAR(100) |
| birth     | DATETIME     |

## 4\. 制約

「制約」とは、カラムに入力できる値に設けるルールのことです。
MySQLなどのDBMSでは、テーブル定義の際に、各カラムに「制約」を指定します。

制約を設けることで、以下のメリットがあります。

- 不正な値が入力されることを防ぐ
- 値が重複してしまうことを防ぐ
- 値の関連性に矛盾が起きることを防ぐ

以下で、代表的な「制約」を7つ説明します。

### 4-1\. NOT NULL

「NOT NULL」制約は、カラムに「NULL」が入力することを拒否できます。
主に、必須入力のカラムに指定されます。
値がない状態（NULL）を拒否するため、値を何も指定しない場合はエラーとなります。

下のSQL文では、usersテーブルのカラムuser_nameに「NOT NULL」を指定しています。

```SQL
CREATE TABLE users(
      user_name VARCHAR(30) NOT NULL
);
```

### 4-2\. DEFAULT

INSERT文で、入力値が指定されなかった場合の初期値を設定します。
値が指定された場合は入力値が、値が指定されなかった場合は初期値が格納されます。
前述の「NOT NULL」制約とよくセットで使われます。
「NOT NULL」と「DEFAULT」を共に指定すると、値が入力されなかった場合も初期値が格納されるため、エラーになりません。
基本的に、特別にNULLを許可したいカラム以外は、すべて「NOT NULL」を指定し、「DEFAULT」で初期値を設定することが望ましいでしょう。

下のSQL文では、productテーブルのカラムpriceに「NOT NULL」と「DEFAULT」で初期値100を指定しています。
これにより、値が入力された場合は入力値が、値が入力されなかった場合は初期値の100が格納されるため、カラムにNULLが格納されることはありません。

```SQL
CREATE TABLE product(
      price INTEGER NOT NULL DEFAULT 100
);
```

### 4-3\. UNIQUE

ある列の値が、重複してはならない場合に指定します。
なお、「UNIQUE」制約が指定されていても、NULLが格納された行が複数あることは許容されるので、注意が必要です。

下のSQL文では、usersテーブルのカラムemailに「UNIQUE」を指定しています。これにより、同じemailが他のレコード（行）に格納される状態を防ぐことができます。

```SQL
CREATE TABLE users(
      email VARCHAR(100) UNIQUE
);
```

### 4-4\. CHECK

格納される値が妥当であるかを判定したい場合に指定します。「CHECK」キーワードの後の条件式が真である値のみ、値が格納されます。

下のSQL文では、productテーブルのカラムpriceに「CHECK」の後に条件式を記述し、0以上の値のみ格納されるように指定しています。値が0未満で条件式が偽となる場合は、エラーとなり、値は格納されません。

```SQL
CREATE TABLE product(
      price INTEGER CHECK(price >= 0)
);
```

### 4-5\. PRIMARY KEY

その列を「主キー」と指定する場合に用います。

「主キー」とは、テーブル内のあるカラムを一意に識別するための特別な値です。
主キーやそれに類する働きをもつ列が存在しないと、同じ内容が格納されたレコード（行）を区別することができなくなります。

主キーに求められる、性質は以下の通りです。

- 一意であること（重複の禁止）
- 空の値（NULL）でないこと
- 一度決めた値を、基本的に変更しないこと
- 1つのテーブルに1つだけ定めること（ただし、複合キーを設定することは可能）

「PRIMARY KEY」を指定すると、対象カラムには自動的に「NOT NULL」制約と「UNIQUE」制約も課されます。

主キーは単独列に指定することが望ましいですが、複数の列の値の組み合わせで主キーとする「複合主キー」を指定することもできます。

単独の列に主キーを設定するには、列名の後ろに記述します。

```SQL
CREATE TABLE users(
      id INTEGER PRIMARY KEY -- 単独の主キー
);
```

複数の列を組み合わせて主キーとする場合は、「CREATE TABLE」文の最後に記述します。

```SQL
CREATE TABLE users(
      user_name VARCHAR(50) UNIQUE,
      email VARCHAR(100) UNIQUE,
      PRIMARY KEY(user_name, email)-- 複合主キー
);
```

### 4-6. FOREIGN KEY と REFERENCES

その列を「外部キー」と指定する場合に用います。

「外部キー」とは、他のテーブルの主キーを参照するための列で、複数のテーブルを紐づける役割を持ちます。
「外部キー」を設定することで、参照整合性が崩れる操作をエラーとして拒否することができます。

参照整合性とは、外部キーで利用する値が、参照先のテーブルに存在しており、テーブル間の紐づけが有効である状態のことを言います。
参照整合性が崩れるような操作とは、具体的に以下のような操作を指します。（説明の上では、外部キーが格納されているテーブルを「参照元テーブル」、外部キーが参照する先のテーブルを「参照先テーブル」と呼称します）

- 参照元テーブルから参照されているカラムの主キーを、参照先テーブルから削除してしまう
- 参照元テーブルから参照されているカラムの主キーを、変更してしまう
- 参照先テーブルに存在しない主キーを、参照元テーブルに外部キーとして追加してしまう
- 参照元テーブルにおいて、参照先テーブルに存在する外部キーを存在しない外部キーに変更してしまう

以下のSQL文で、テーブル定義の最後にmanufacturer_idを、manufacturer外部テーブルと紐づける外部キーと指定しています。

```SQL
-- 参照整合性を保つため、参照先となるmanufacturerテーブルを先に作成する必要がある
CREATE TABLE manufacturer(
      manufacturer_id INTEGER PRIMARY KEY,  -- 参照先の主キー
      manufacturer_name VARCHAR(30) NOT NULL,
      manufacturer_email VARCHAR(100) NOT NULL,
      manufacturer_address VARCHAR(100) NOT NULL
);

CREATE TABLE product(
      product_id INTEGER PRIMARY KEY,
      product_name VARCHAR(30) NOT NULL,
      price INTEGER DEFAULT 0 CHECK(price >= 0),
      manufacturer_id INTEGER,
      FOREIGN KEY (manufacturer_id) REFERENCES manufacturer(manufacturer_id)-- 外部キー
);
```

### 4-7. AUTO_INCREMENT

「AUTO_INCREMENT」を指定することで、テーブルにレコードが追加されるたびに、自動的にインクリメントされた値がセットされます。
1つのテーブルに1列だけ指定可能です。
値はインクリメントされるため、「AUTO_INCREMENT」を指定する列のデータ型は、整数型である必要があります。
また、整数値の負の値を許容する必要がないため、正の値の最大値を増やす「UNSIGNED」を付与する場合もあります。

以下のSQL文では、usersテーブルに「AUTO_INCREMENT」で自動的にインクリメントされた整数を格納する主キーのidカラムを作成します。


```SQL
CREATE TABLE users(
      id INTEGER UNSIGNED AUTO_INCREMENT PRIMARY KEY
);
```

## まとめ

- DDL（データ定義言語）の役割: CREATE, ALTER, DROP文でデータベースやテーブルを定義・管理する

- 適切な初期設定の重要性: CHARACTER SET (utf8mb4) や ENGINE (InnoDB)、COLLATE など、用途に合わせた適切な設定が、後のシステム拡張性やパフォーマンスに直結する。

- 制約によるデータ品質の担保: PRIMARY KEY や FOREIGN KEY、NOT NULL などの制約を適切に設計することでデータ整合性を実現できる

- 実務におけるリスク管理: DROP 命令などの破壊的な操作に対しては、実行権限の制限や RENAME による段階的な廃止など、運用面での配慮が不可欠である
