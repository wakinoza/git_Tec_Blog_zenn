## はじめに

- AWS SOAの取得を目指して勉強中です。
- 間違い等あれば、指摘いただけると助かります。

## 結論

- Lambdaをユーザー管理VPCに接続すると、Hyperplane ENIを介して、プライベートサブネットに配置されたRDSやEC2などのリソースにアクセスできるようになります。
- Lambdaの実行環境そのものがユーザー管理VPCに移動するわけではなく、AWSが管理する実行環境からHyperplane ENIを介して通信します。
- VPCに接続したLambdaは、デフォルトではインターネットにアクセスできません。インターネットへのアウトバウンド通信には、NAT Gatewayなどを利用したネットワーク経路の構築が必要です。
- NAT Gatewayをパブリックサブネットに配置し、プライベートサブネットのルートテーブルからNAT Gatewayへ通信を転送することで、Lambdaからインターネットへアクセスできるようになります。

## 1. Lambdaとは

Lambdaは、AWSが提供するサーバーレスコンピューティングサービスです。

サーバー「レス」とは、「サーバーがない」という意味ではなく、「サーバーの構築や管理をユーザーが行う必要がない」という意味です。

通常、EC2などを利用してアプリケーションを実行する場合、ユーザーはサーバーの起動やOSの管理、リソースの確保などを行う必要があります。

一方、Lambdaでは、実行するコードを用意すれば、AWSが管理する実行環境でコードを実行できます。
サーバーの構築や管理をユーザーが意識することなく、処理を実行できるのが特徴です。

### 1.1 Lambdaの実行環境

Lambdaは、AWSが管理する実行環境で動作します。

この実行環境には、コードを実行するためのランタイム（PythonやJavaなどの実行基盤）が用意されています。

Lambdaは、イベントをトリガーとして、必要に応じて実行環境を準備・再利用しながら処理を実行します。
Lambdaへのイベントの受け渡し方式には、イベント元がLambdaを呼び出す「プッシュ型」と、Lambdaのイベントソースマッピングがイベント元のデータを継続的に取得する「ポーリング型」の2種類があります。
Lambdaを呼び出すイベントの例は、以下の通りです。

| イベント呼び出し元 | イベントの発生・検知方法 | 方式 |
| ---- | ---- | ---- |
| API Gateway | HTTPリクエストを受信するとLambdaを呼び出す | プッシュ型 |
| S3 | ファイルのアップロードなどを検知してLambdaに通知 | プッシュ型 |
| EventBridge（イベント） | AWSサービスなどで発生したイベントを検知してLambdaに通知 | プッシュ型 |
| SNS | トピックにメッセージが発行されるとLambdaに通知 | プッシュ型 |
| SQS | イベントソースマッピングがキューからメッセージを取得 | ポーリング型 |
| DynamoDB Streams | イベントソースマッピングがストリームから変更データを取得 | ポーリング型 |


また、Lambda実行環境の再利用や、処理量に応じたスケーリングもAWSが担っているため、ユーザーがサーバーの台数や起動・停止を管理する必要はありません。

### 1.2 Lambdaのネットワーク環境

Lambdaの実行環境は、AWSが管理するVPC内で動作し、インターネット上のAPIやWebサービスにアクセスできます。

例えば、Lambdaから外部のWeb APIにHTTPリクエストを送信したり、インターネット上のサービスからデータを取得したりできます。

また、ユーザーが管理するVPC内のリソースであっても、パブリックIPアドレスを持ち、インターネット経由でアクセスできるように設定されていれば、Lambdaから接続できます。

一方、ユーザーが管理するVPC内のプライベートIPアドレスを持つリソースには、直接アクセスできません。

例えば、プライベートサブネットに配置されたRDSに接続したい場合は、Lambdaをユーザーが管理するVPCに接続する必要があります。


## 2. LambdaのVPC接続

### 2.1 LambdaをVPCに接続する理由

1章で説明したとおり、VPCに接続していないLambdaは、ユーザーが管理するVPC内のプライベートIPアドレスを持つリソースに直接アクセスできません。

例えば、プライベートサブネットに配置されたRDSにLambdaから接続したい場合、LambdaとRDSの間にプライベートなネットワーク接続が必要になります。

このような場合に利用するのが、LambdaのVPC接続機能です。

Lambdaをユーザーが管理するVPCに接続することで、VPC内のプライベートサブネットに配置されたEC2やRDSなどのリソースにアクセスできるようになります。

### 2.2 Hyperplane ENIとは

LambdaをVPCに接続すると、AWSは指定されたサブネットとセキュリティグループに基づいて、「Hyperplane ENI」を作成します。

ENI（Elastic Network Interface）とは、VPC内のリソースにネットワーク接続を提供する仮想ネットワークインターフェイスです。

Lambdaをユーザー管理VPCに接続しても、Lambdaの実行環境そのものがユーザー管理VPC内に移動するわけではありません。
AWSが管理するVPC内で動作するLambdaの実行環境から、Hyperplane ENIを介してユーザーVPC内のリソースへ通信できるようになる、という仕組みです。
Lambdaの実行環境は、VPC接続後も引き続きAWSが管理するVPCで動作しています。

Hyperplane ENIは、VPCピアリングと似ていますが、通信方式が異なります。
VPCピアリングは、2つのVPC間にプライベートな通信経路を構築し、ルートテーブルなどの設定によって双方向の通信を可能にする仕組みです。

一方、Hyperplane ENIは、AWS HyperplaneによるVPC間NAT（VPC-to-VPC NAT）とクロスアカウント接続を利用し、Lambdaの実行環境からユーザーVPC内のリソースへアクセスできるようにする仕組みです。
そのため、ユーザーVPC側からLambdaの実行環境へ直接接続することはできません。ただし、Lambdaから開始した通信に対する応答は受信できます。

Hyperplane ENIの作成や管理はAWSが行うため、ユーザーが手動でENIを作成する必要はありません。

また、AWSは高可用性を確保するため、複数のAZ（アベイラビリティゾーン）にあるサブネットを指定することを推奨しています。これにより、特定のAZで障害が発生した場合にも、別のAZを利用できる構成にできます。

## 3. VPCに接続したLambdaからインターネットへアクセスする

LambdaをVPCに接続すると、ユーザーVPC内のプライベートサブネットに配置されたRDSなどのリソースにアクセスできるようになります。

しかし、VPCに接続したLambdaは、デフォルトではインターネットにアクセスできなくなります。

これは、Lambdaからの通信がユーザーVPCのネットワーク経路を利用するようになるためです。
ユーザーVPC側にインターネットへの通信経路が用意されていない場合、Lambdaも外部ネットワークへ接続できません。

また、仮にLambdaをInternet Gatewayへのルートが設定されたパブリックサブネットに接続しても、LambdaにはパブリックIPアドレスが自動的に割り当てられません。

そのため、通常のEC2のようにInternet Gatewayを経由して直接インターネットに接続することはできません。

VPCに接続したLambdaからインターネットへアクセスするには、NAT Gatewayなどを利用して、外部ネットワークへの通信経路を構築する必要があります。

## 4. LambdaをVPCに接続し、NAT Gateway経由でインターネットへ接続する

この章では、LambdaをVPCに接続する方法、VPCに接続したLambdaをNAT Gateway経由でインターネットへ接続する方法について、具体的な設定方法を説明します。

### 4.1 LambdaをVPCにアタッチするための設定

Lambdaをユーザー管理VPCに接続するには、Lambdaの設定画面から接続先のVPC、サブネット、セキュリティグループを指定します。

それぞれの役割は以下のとおりです。

| 設定項目             | 役割                                                         |
| -------------------- | ------------------------------------------------------------ |
| VPC                  | Lambdaから接続するネットワークを指定する                     |
| サブネット           | Hyperplane ENIを作成するサブネットを指定する。異なるAZにある複数のサブネットを選択することが推奨される       |
| セキュリティグループ | LambdaのHyperplane ENIに適用し、Lambdaからの通信やLambda宛ての通信を制御する |

例えば、ユーザーVPC内のプライベートサブネットのRDS（MySQL）へLambdaから接続したいとします。
その場合は、Lambda用のセキュリティグループと、RDS用のセキュリティグループを作成します。

Lambda外部から直接接続を受け付けるサーバーではないため、通常はセキュリティグループでインバウンドルールを設定する必要はありません。
アウトバウンドルールで、LambdaからRDSのMySQLポート（3306番）への通信を許可します。
なお、セキュリティグループはステートフルであるため、Lambdaから開始した通信に対する戻りの通信は、自動的に許可されます。

【Lambda用セキュリティグループの設定例】
アウトバウンドルール

| タイプ      | プロトコル      | ポート  | 宛先      |
| --------- | ---------------- | ---------------- | ---------------- |
| MySQL/Aurora | TCP           |  3306 |  RDS用SG |

RDSのセキュリティグループでは、インバウンドルールで、Lambdaのセキュリティグループからの通信を許可します。


【RDS用セキュリティグループの設定例】
インバウンドルール

| タイプ       | プロトコル | ポート | ソース    |
| ------------ | ---------- | ------ | ------- |
| MySQL/Aurora | TCP        | 3306   | Lambda用SG |

また、Lambdaの実行ロールには、ENIを作成・管理するためのIAM権限が必要です。

AWSが提供する管理ポリシー「AWSLambdaVPCAccessExecutionRole」を実行ロールに付与することで、必要な権限を設定できます。
このポリシーには、ENIの作成や削除、情報の取得などに必要な権限が含まれています。
VPC設定が完了した後は、最小権限の原則に従ってポリシーを削除することも可能です。

### 4.2 NAT Gatewayを経由したインターネット接続の設定

VPCに接続したLambdaからインターネットへアクセスするには、NAT Gatewayを利用する方法が一般的です。

NAT Gatewayは、プライベートIPアドレスを持つリソースからインターネットへの通信を中継するAWSのマネージドサービスです。

Lambdaの実行環境からHyperplane ENIを経由して、ユーザーVPC内のプライベートサブネットを通じてインターネットへ通信する場合、次のような経路を構築します。

1. パブリックNAT Gatewayをパブリックサブネットに作成する
2. NAT GatewayにElastic IPを割り当てる
3. パブリックサブネットのルートテーブルにInternet Gatewayへの経路を設定する
4. Lambdaを接続したプライベートサブネットのルートテーブルにNAT Gatewayへの経路を設定する
5. Lambdaに設定したセキュリティグループのアウトバウンドルールで、インターネットへの通信を許可する


ルートテーブルは、次のように設定します。

【パブリックサブネットのルートテーブルの設定例】

| 宛先      | ターゲット       |
| --------- | ---------------- |
| VPCのCIDR | local            |
| 0.0.0.0/0 | Internet Gateway |

【プライベートサブネットのルートテーブルの設定例】

| 宛先      | ターゲット  |
| --------- | ----------- |
| VPCのCIDR | local       |
| 0.0.0.0/0 | NAT Gateway |

このルートを設定することで、VPC内の宛先に該当しない通信は、それぞれInternet GatewayまたはNAT Gatewayへ転送されます。

また、セキュリティグループのアウトバウンドルールで、インターネットへの通信が許可されていることも確認します。

【Lambda用セキュリティグループの設定例】
アウトバウンドルール

| タイプ       | プロトコル | ポート | 宛先    |
| ------------ | ---------- | ------ | ------- |
| MySQL/Aurora | TCP        | 3306   | RDS用SG |
| HTTPS | TCP        | 443  | 0.0.0.0/0 |

### 4.3 Lambdaからインターネットへ通信する際の経路

ここまでの設定によって、Lambdaからインターネットへ通信できるようになります。

通信の流れを整理すると、次のようになります。

1. Lambdaの実行環境からHyperplane ENIを経由して、ユーザーVPCへ通信する
2. Hyperplane ENIが配置されたサブネットのルートテーブルを参照し、NAT Gatewayへ通信を転送する
3. NAT Gatewayが送信元のプライベートIPアドレスを、割り当てられたElastic IPに変換する
4. NAT GatewayからInternet Gatewayを経由して、インターネット上の宛先へ通信する

戻りの通信は、NAT Gatewayが管理する変換情報をもとに、元の送信元へ転送されます。

このように、NAT Gatewayを利用することで、LambdaにパブリックIPアドレスを割り当てることなく、インターネットへのアウトバウンド通信を実現できます。

NAT Gatewayは、インターネット側から開始された新規接続を受け付けるものではありません。
そのため、プライベートサブネット内のリソースをインターネットに直接公開することなく、外部への通信を可能にできます。
