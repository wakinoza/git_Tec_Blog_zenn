## 1\. Linux 起動プロセス

Linux OSが入ったコンピュータの電源を入れて、しばらくするとログイン画面が表示されます。
この電源からシステムが起動するまでの間には、複数のプログラムが段階的に処理を引き継ぎながら起動する「ブートストラップ」という仕組みがあります。

この章では、システム起動までの各工程について解説していきます。

| 順番 | 起動するプログラム       | 働き                                            |
| --- | ------------------------ | ----------------------------------------------- |
| 1   | 電源を入れる             | BIOS/UEFIの実行開始                             |
| 2   | BIOS/UEFIの実行          | ハードウェアの初期化とブートローダーの読み出し  |
| 3   | ブートローダーの実行     | カーネルの読み出し                              |
| 4   | カーネルの実行           | ルートファイルシステムのマウント                |
| 5   | 初期プロセスの実行       | 最初のプロセスであるinit（またはsystemd）を実行 |
| 6   | 各サービス起動           | 必要なサービスを順次または並列に立ち上げ        |
| 7   | ログインプロンプトの表示 | ユーザーの操作を受け付ける状態になる            |

### 1.1\. 電源を入れる
電源が入ると、CPUがマザーボードのフラッシュROM上にある「BIOS（もしくはUEFI）」を実行します。

### 1.2\. BIOS/UEFIの実行（ハードウェアの初期化）
BIOS（Basic Input Output System）とUEFI（Unified Extensible Firmware Interface）は、OSが起動する前に動作し、ハードウェアの管理と制御を行うプログラムです。
BIOSは1970年代から利用されているプログラムで、BIOSの後継としてUEFIが開発されました。2010年頃よりUEFIへの移行が開始され、現在ではUEFIが主流となっています。

BIOS/UEFIが起動すると、PCに接続されている各種デバイスの初期化を行います。起動時にハードウェアの自己診断を行う処理をPOST（Power On Self Test）といいます。
POSTが終了すると、ブートローダーの読み込みに移ります。

まず、BIOS設定や起動優先順位に基づき、HDDやCD-ROMなどから「起動ドライブ」（最初に読み込むデバイス）を決定します。
起動ドライブが決まると、BIOSでは、MBRやBIOS Boot Partitionに配置されたブートコードを利用して、後続のブートローダー本体（core.img等）を読み出します。
UEFIでは、GPT（GUID Partition Table）上のEFIシステムパーティション（ESP）内にあるブートローダーファイルを直接読み出します。
このように、ハードウェア環境に応じた仕組みで最終的にブートローダーがメモリ領域に読み出されます。

ブートローダーが起動したのちは、制御をブートローダーに移します。

### 1.3\. ブートローダー起動（カーネルの読み込み）
ブートローダーとは、カーネル（Linuxの中核を担うプログラム）を起動するプログラムです。
ブートローダーは、ストレージ上のカーネルをメモリ領域に読み出します。この際、カーネルパラメータ（OSの挙動を制御する設定項目）や最小限のドライバセットである「initramfs」もメモリ上に展開します。

Linuxのブートローダーには、歴史的にGRUBが使われてきましたが、現在はGRUB2がデファクトスタンダードとなっています。

### 1.4\. カーネル起動 （ルートファイルシステムのマウント）
起動したカーネルは、メモリの初期化やクロックの設定を行った後、システム運用の根幹となる「ルートファイルシステム」へのアクセスを試みます。

「ルートファイルシステムをマウント」とは、ディスク（HDDやSSD）上のバイナリデータをファイルシステムとして解釈し、ディレクトリツリー（/）に組み込むことで、ファイル操作を可能にすることです。

しかし、起動直後のカーネルは、ディスクを読み出すことができません。
それは、ディスクを読み出すための「ディスクドライバ」がディスクのなかに保存されているためです。まるで、部屋に入りたいのに部屋の鍵が部屋の中にあるようなもので、カーネルはディスクにアクセスできません。

この状態を解決するのが、ブートローダーによってカーネルと共にメモリ上へロードされる一時的なルートファイルシステム「initramfs」です。
initramfsには、ディスクアクセスに必要なデバイスドライバや、初期化用の最低限のユーザー空間ツール群が格納されています。
カーネルは、まずメモリ上のinitramfsを利用し、その中のデバイスドライバを読み込むことで、ルートファイルシステムをマウントする準備を整えるのです。

### 1.5\. 初期プロセスの実行 (最初のプロセスであるinitを実行)

ルートファイルシステムがマウントされると、カーネルはユーザー空間の最初のプロセス（PID 1）として /sbin/init を実行します。これは全プロセスの親となる特別なプロセス（PID 1）です。
init（またはsystemd）については、後の章で詳しく説明します。

### 1.6\. 各サービス起動 (必要なサービスを順次または並列に立ち上げ)

init/systemdが設定に従い、ネットワークやGUI環境などの必要なサービスを順次または並列に立ち上げます。

### 1.7\. ログインプロンプトの表示

起動が完了するとログインプロンプトが表示され、ユーザーの操作を受け付ける状態になります。

## 2\. SysVinitとsystemd

カーネルが起動した後、最初に実行されるプロセスを「PID 1（プロセスID 1）」と呼びます。 プロセスは「子プロセス」「孫プロセス」と派生しながら実行していくため、 PID 1はすべてのプロセスの親に当たります。ログイン画面やWebサーバーなど、後から起動するすべてのプログラムは、このPID 1から派生して作られます。
PID 1は、システム全体の管理者としての役割も持っています。サービスに不具合があった場合に再起動したり、システム終了時に安全にプロセスを止めたりするための司令塔の役割を果たします。

PID 1の実行を制御するプログラムは時代によって変化しています。
1980年代～ SysVinit
2000年代～ Upstart（主にUbuntu系で採用）
2010年代～ systemd

この記事では、LinuCに頻出するSysVinitとsystemdを取り上げ、その違いを見ていきます。

## 2.1\. SysVinit

PID 1として動作するプログラム : /sbin/init
実行方式 : シェルスクリプトを逐次実行
プロセス管理 : PID
起動の流れ : init プロセスが /etc/inittab を読み込み、システムの初期化から、ランレベルに応じたサービスを順に呼び出します。

1. initプロセス開始
2. /etc/inittabファイルを読み込み、記載されたプロセスを順に起動
  2-1. 「システム初期化スクリプトを実行」（例: RHEL系における /etc/rc.d/rc.sysinitなど）
  ランレベルに関係なく実行する処理。ネットワークの初期設定やホスト名の設定、ファイルシステムの整合性チェック、デバイス管理の開始といった、システムが安定して動作するための基盤的な初期化処理を実行します。
  2-2. 「rcスクリプトを実行」（/etc/rc.d/rcスクリプト）
  ランレベルに応じたサービスを起動
  2-3. /etc/rc.d/rcスクリプトが、指定されたランレベルに対応するディレクトリ（例: /etc/rc.d/rcN.d/）配下のスクリプト群を呼び出して実行」

「ランレベル」は、カーネルが起動したあと、システムを「どの程度のフル機能で動かすか」という動作モードを数字で表したものです。ランレベルで分離されているおかげで、状況に応じて必要な実行環境を選択できます。
例えば、通常の起動ができない場合でも、レベル1（シングルユーザーモード）で起動して、壊れた設定ファイルを直すことができます。画面操作が不要な本番サーバーでは、あえてレベル3（CUI）で起動させることで、GUIに使う余計なメモリやCPUを節約します。

| ランレベル | モード名         | 特徴・使いどころ                                                                     |
| ---------- | ---------------- | ------------------------------------------------------------------------------------ |
| 0          | Halt（停止）     | システムを終了する状態                                                               |
| 1          | Single User      | ネットワークも使えない、管理者一人だけの状態。パスワード忘れやシステムの復旧に使う   |
| 3          | Multi User (CUI) | ネットワークが使え、複数のユーザーがログインできる。サーバーとして運用する際の標準。 |
| 5          | Multi User (GUI) | レベル3に加えて、マウスで操作できるデスクトップ画面が立ち上がる状態。                |
| 6          | Reboot（再起動） | システムを再起動する状態                                                             |

SysVinitはサービスをシェルスクリプトによって順次（直列）起動するため、特定のサービスの初期化待ちがシステム全体の起動時間に直結するという課題がありました。

## 2.2\. systemd

SysVinitの欠点を克服するために生み出された新しいプログラムが、systemdです。

PID 1として動作するプログラム : /lib/systemd/systemd
（互換性維持のため、/sbin/init がこの実体へのシンボリックリンクとして配置されるのが一般的です）
実行方式 : Unit単位で管理。依存関係を解析し、可能な限り並列処理。
プロセス管理 : cgroups
起動の流れ : systemdプロセスが、最初に読み込まれるdefault.targetを読み込み、依存関係に従いながら、必要なサービスを並列処理していく。

systemdの特徴は、システムを構成するリソースを「Unit」という設定ファイル単位で管理する点にあります。
Unitには機能ごとに拡張子が割り当てられており、拡張子を見ることでUnitの機能が判別できます。

| 拡張子   | 機能                                    |
| -------- | --------------------------------------- |
| .device  | 各種デバイスを管理                      |
| .mount   | ファイルシステムのマウントを管理        |
| .service | サービスを制御                          |
| .swap    | スワップ領域を管理                      |
| .target  | 複数のサービスを1つのグループにまとめる |

システム起動時に最初に読み込まれるUnitは「/etc/systemd/system/default.target」です。「default.target」を用途に合うターゲットUnitへのシンボリックリンクとして作成することで、期待するサービス群を起動できるようになります。
ターゲットUnit には複数の種類があり、それぞれSysVinitのランレベルに対応しています。

| SysVinitランレベル | systemdターゲットUnit | 特徴・使いどころ                                                                     |
| ------------------ | --------------------- | ------------------------------------------------------------------------------------ |
| 0                  | poweroff.target       | システムを終了する状態                                                               |
| 1                  | rescue.target         | ネットワークも使えない、管理者一人だけの状態。パスワード忘れやシステムの復旧に使う   |
| 3                  | multi-user.target     | ネットワークが使え、複数のユーザーがログインできる。サーバーとして運用する際の標準。 |
| 5                  | graphical.target      | レベル3に加えて、マウスで操作できるデスクトップ画面が立ち上がる状態。                |
| 6                  | reboot.target         | システムを再起動する状態                                                             |

また、systemdでは、Linuxカーネルの機能であるcgroupsを活用し、プロセスをグループ化して管理します。これにより、特定のサービスがCPUやメモリを食いつぶすのを防ぐほか、サービスに関連する子プロセスを一括で確実に停止できる高い管理能力を実現しています。

また、systemdによる起動高速化の実現には、ソケットアクティベーションという技術が貢献しています。ソケットアクティベーションとは、サービス本体の起動に先立ち、通信エンドポイント（ソケット）を先行して生成する仕組みを指します。
従来のLinuxの起動プロセスでは、サービス間に依存関係がある場合、前のサービスが完全に立ち上がり、通信ポート（ソケット）を開くのを待ってから次のサービスを起動していました。この「待ち時間」がシステムの起動を遅らせる一因となっていました。
これを解決するのが、systemdのソケットアクティベーションです。
ソケットアクティベーションでは、サービス本体が起動する前に、systemdが先に「通信窓口（ソケット）」だけを作成してしまいます。サービスAは、ソケットさえあればデータをそこに「預ける」ことができるため、サービスBの起動完了を待たずに処理を継続できます。
また、ソケットはデータの流入を監視しており、データが格納された瞬間に次のサービスを呼び出します。
ソケットを先に用意することで、サービス同士を疎結合にし、起動時の依存関係によるタイムロスを徹底的に排除する。この仕組みによって、システム起動の高速化が実現しているのです。

## 3\. なぜ「ブートローダー」が必要なのか？

BIOS/UEFIがブートローダーをメモリ上に読み出し、そのブートローダーがカーネルをメモリ上に読み出しています。
カーネルを読み出すことが目的であるなら、BIOS/UEFIが直接カーネルを読み出せばよいのではと思う方もいるかもしれません。

実際に、高機能化したUEFIの一部には、ブートローダーを介さず直接カーネル起動する機能（EFI boot stub）も存在します。

直接起動する技術が存在する一方で、現在もブートローダーを介する構成が一般的です。
その理由は、以下の3点に集約されます。

1. 役割の分離 : BIOS/UEFIは本来ハードウェアの制御を目的としたファームウェアです。そのため、ソフトウェアの制御は、BIOS/UEFIの管轄外と言えます。ハードウェア層（BIOS）から仲介層（ブートローダー）へ、そしてソフトウェア層（カーネル）へと段階を踏むことで、役割を明確に分けています。
2. 容量と技術的制約の克服 : BIOS/UEFIは、マザーボード上のフラッシュROMに書き込まれた軽量なファームウェアであり、保持できるプログラムサイズに制約があります。特に従来のBIOS環境では、扱える機能が限定的であり、数MB〜数十MBものカーネルを読み出す機能がありません。カーネルが保存されている複雑なファイルシステムを解釈したり、CPUのモードを切り替えたり、メモリの適切な位置に展開したりするなどの高度な機能もBIOS/UEFIにはありません。
3. 疎結合と柔軟性 : もしBIOSが直接カーネルを読み出す仕組みだと、新しいOS（新しいカーネルの形式）が出るたびに、マザーボード上のBIOSを書き換えなければならなくなります。しかし、ハードウェア領域とソフトウェア領域の間に、ブートローダーという仲介役を配置し「疎結合」にすることで柔軟性が向上します。具体的には、マザーボードのBIOSを書き換えることなく複数のOSを選択して起動する「マルチブート」も容易に実現可能です。また、OSが壊れた際の復旧モード起動など、起動時のパラメータ変更も柔軟に行えるようになります。


## まとめ

- Linuxの起動は、「BIOS/UEFI → ブートローダー → カーネル → init/systemd」という順番で進む

- ブートローダーは、カーネルとinitramfsをメモリ上に読み出し、OS起動を支援する

- initramfsには、ルートファイルシステムをマウントするために必要な最低限のドライバやツールが含まれている

- SysVinitはランレベルで動作モードを管理し、サービスを順次起動する

- systemdはUnitとcgroupsを利用し、依存関係を解析しながらサービスを並列起動することで、高速かつ効率的なシステム管理を実現している
